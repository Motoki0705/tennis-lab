# アレーと短い追跡断片に対する選手選別の比較

## 保存済み55クリップでの原因の再現

[#2363の全件実行](../run-i2363-trt-player-video/README.md)で生成できた55クリップを調べた。3D関節のinlierを1つ以上持つカメラが2台未満だった5,201選手フレームを抽出し、4視点それぞれで観測をさかのぼった。[集計と各クリップの内訳](loss.json)

| 落ちた段階 | 2026-11-23の集計 | 再実行 | 割合 |
| --- | ---: | ---: | ---: |
| 参照なし・画面外 | 3,100 | 3,100 | 14.9% |
| DINOのboxが2.0 m以内にない | 2,179 | 2,179 | 10.5% |
| 追跡なし | 49 | 49 | 0.2% |
| 選別外れ | 10,853 | 10,853 | 52.2% |
| カメラ間で選手に割り当てられない | 34 | 34 | 0.2% |
| 割当済みで他の支持視点がない | 4,589 | 4,589 | 22.1% |
| 合計 | 20,804 | 20,804 | 100% |

位置の参照は同じフレームの他の割当済み視点から作った。box下端中央を保存済みホモグラフィでコート平面に戻し、向きを合わせて平均した。対象カメラでその位置が画面内にあれば、最も近い検出boxを2.0 mまで採り、保存rowから追跡、選別のgroup、人物IDまでたどった。対応で落ちた34件はすべて別の選手IDへの割当だった。割当の誤りと足元の投影誤差が分類に影響する。

選別外れのうち、領域外は6,707件で、うち6,702件が横境界を越え、5,685件は他視点の平均位置も領域外だった。領域内は4,146件で、うち2,657件はチェーンに含まれる断片の観測数の合計が必要滞在数を下回った。画像下端で足元を失ったケースは0件。元集計はx・yをミリメートルに丸めてから判定していた。丸め前は領域外6,711件、領域内4,142件だった。どちらも選別外れの合計は10,853件となる。

停止した020と058では、コート向きを合わせた後の正側ベースライン近くで、アレーに長く残った未採用トラックを各視点で確認した。表の `観測 / 最長滞在` は当該raw trackの全実観測数と、同trackを含むチェーンのシングルス領域内での最大滞在数。8視点すべてで選別された観測は0件だった。

| clip | 必要滞在 | cam0 | cam1 | cam2 | cam3 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 020（651フレーム） | 162.75 | 649 / 0 | 649 / 0 | 403 / 0 | 649 / 0 |
| 058（765フレーム） | 191.25 | 596 / 11 | 763 / 4 | 763 / 154 | 763 / 0 |

該当トラックの足元の中央値は `|x| = 4.453–5.159 m`、`y = 12.067–14.084 m`。020のcam2は観測がクリップの62%に限られ、058のcam2には154フレームの滞在があった。どちらも保存進捗の停止理由は `Side y>0 lacks 2 identities` だった。[トラックID、境界、フレーム数](loss.json)

## 比較条件

| 条件 | 滞在・連結の領域 | 必要な領域内の実観測 |
| --- | --- | ---: |
| 旧既定（`baseline`） | シングルス幅 `\|x\| ≤ 4.115 m` | 25% |
| 新既定（`wide`） | ダブルス幅 `\|x\| ≤ 5.485 m` | 25% |
| 滞在の短縮（`short`） | シングルス幅 `\|x\| ≤ 4.115 m` | 12.5% |
| 併用（`wide_short`） | ダブルス幅 `\|x\| ≤ 5.485 m` | 12.5% |

全条件で縦境界は `|y| ≤ 16.885 m`、連結後に実観測フレームを重複なく数え、視点別の上限は6チェーン。12.5%は断片化への対照として25%を半分にした。標準経路では試合形式にかかわらず新既定を使い、対応付けの人数を `players_per_side` で指定する。[標準経路の設定](../../../src/tennis_scene/pipeline/README.md)

### meiji_4camの全69クリップ

保存した追跡・関節・外観特徴・コート校正から、選別、選手を使ったコート向きの判定、カメラ間対応、カメラ整合の検査、3D関節の三角測量をCPUで再実行した。選別後のCLIP外観は各条件で選んだcropのフレームに対応する保存済み特徴を使った。全条件の選別済み観測に外観特徴が揃っていた。3Dはカメラと全関節入力が一致する場合に保存済みの結果を使用した。037で保存結果を使わずに実行し、条件ごとの集計が一致した。旧既定は#2363の選別mask・group出自を全276視点で再現し、完了55件の人物割当と各フレームの3D選手数、停止14件の理由も一致した。

| 条件 | 選別した生観測 | 3D選手フレーム | 旧既定からの増加 / 減少 | 停止 | 復帰 / 新規停止 |
| --- | ---: | ---: | ---: | ---: | --- |
| 旧既定 | 659,568 | 133,887 | 0 / 0 | 14 | 0 / 0 |
| 新既定 | 688,290 | 147,105 | 13,218 / 0 | 11 | 012・020・058 / 0 |
| 滞在の短縮 | 683,151 | 136,212 | 8,648 / 6,323 | 14 | 012・058 / 044・064 |
| 併用 | 703,599 | 141,398 | 9,913 / 2,402 | 13 | 020・058 / 044 |

有効な3D関節が1つ以上ある選手IDをフレームごとに数え、旧既定との差を増加と減少に集計した。幅の拡張による増加13,218件のうち、3,527件は旧既定でも三角測量まで進んだクリップに含まれる。020では2,579件、058では3,052件だった。滞在の短縮で058の三角測量に進んだ場合は2,289件だった。選別した生観測にはカメラごとの実観測を数え、カメラ間対応前の選別負荷を示す。[全クリップの数値と停止理由](comparison.json)

標準設定への変更後に全69クリップ・276視点を再選別し、4条件の計1,104マスクが比較時の保存結果と一致した。旧既定と新既定でマスクが変わったのは72視点だった。037を三角測量まで再実行した集計も一致した。

ユーザーが #2442 の疑似正解を品質不足で棄却したため、採点を除いた。4カメラの指標は保存された観測からの選別と三角測量の到達状況を示し、選手IDの正しさや非選手の混入率は未測定。

### Meiji 3camの開発用4クリップ

`000/000`・`000/007`・`001/001`・`002/013` の3,497フレームを、元ラベルと対応する `i933-observe-v1-20260927` の保存済み `person_tracks` v3で採点した。全条件ともこの観測の足元と保存校正を使った。シングルス映像にダブルス幅を適用した値も載せた。[クリップ別の採点](singles.json)

| 条件 | 選手box選別 / 参照20,620件 | 非選手box誤選別 / 参照4,454件 | Precision | Recall |
| --- | ---: | ---: | ---: | ---: |
| 旧既定 | 20,038 | 0 | 100% | 97.18% |
| 新既定 | 20,038 | 0 | 100% | 97.18% |
| 滞在の短縮 | 20,386 | 212 | 98.97% | 98.87% |
| 併用 | 20,386 | 212 | 98.97% | 98.87% |

滞在を短くすると007で選手boxが163件、001/001で185件増えた。非選手boxの増加212件は007に集中した。IoU 0.5以上で選別前の追跡boxとラベルをフレーム・視点ごとに一対一で照合した。Precisionの分母は選別した選手・非選手の既知box。Recallの分母は追跡に残らなかったboxも含む全ラベル付き選手box。曖昧な選別box3件と照合不能box0件は別に数えた。4クリップは旧既定の設計にも使われた。測定は当時保存した追跡結果と幾何選別に基づくため、現在の追跡・外観特徴を使う未見シングルスでの精度は未確認。

### 採用と後続の分担

既存経路にダブルス幅・滞在25%を採用した。全69件で新規停止がなく、アレーに立つ選手が外れていた020・058の両方が復帰した。Meiji 3camの開発用4クリップでは選手・非選手の選別が変わらなかった。滞在の短縮を含む条件では4カメラで新規停止が生じ、シングルスで非選手boxが増えた。

既存シーンへの反映は #2460 で行う。新経路は同じダブルス幅を出発点に、複数視点と時間方向の3D軌跡から短い観測断片をつなぎ、選手の滞在を検証する。今回の3D選手フレーム・停止数と、Meiji 3camの選別指標を比較の基準にする。[旧結果への反映 #2460](https://github.com/Motoki0705/tennis-lab/issues/2460)・[3D軌跡での選別 #2445](https://github.com/Motoki0705/tennis-lab/issues/2445)

## 再現手順

`I2363_RUN` は [#2363の出力](../run-i2363-trt-player-video/README.md)の `i2363/i2363-all-v1`、`ARCHIVE_OUTPUTS` は `player_association/evaluate/meiji_clips/i933-observe-v1-20260927` がある保存済みの `outputs`。実行ログと視点・条件ごとの選別診断は `OUT` 以下に保存する。再実行は新しい `OUT` を使う。

```bash
study=knowledge/runs/run-i2440-player-selection
OUT=outputs/i2440-repeat
mkdir -p "$OUT"
export PYTHONPATH="$PWD"
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
.venv/bin/python -B "$study/trace_loss.py" "$I2363_RUN" "$OUT/loss.json"
.venv/bin/python -B "$study/replay.py" "$I2363_RUN" "$OUT/replay" --jobs 7
.venv/bin/python -B "$study/score.py" singles \
  data/tennis_multiview/processed/meiji_3cam/dataset "$ARCHIVE_OUTPUTS" "$OUT/singles.json"
cmp "$study/loss.json" "$OUT/loss.json"
cmp "$study/comparison.json" "$OUT/replay/comparison.json"
cmp "$study/singles.json" "$OUT/singles.json"
```
