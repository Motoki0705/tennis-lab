# Meijiの選手枠への3D断片統合

時間窓で得た3D IDの断片を、同じ側の選手枠に全体最適で割り当てた。前後の集計は同じ `frame_pose_candidates` v1、同じ人手ラベルと採点器を使った。 [初回の時間窓追跡](../run-i2445-multiview-tracking/README.md)・[統合と保存の契約](../../../src/tennis_scene/multiview_tracking/README.md)

## 設定の根拠

- 既存の選別が採用した断片は核として保持する。空き枠には領域内での滞在と、割当の確度・有効関節数を使って暫定の核を選ぶ。各側の全枠について、核を通る非重複のパスを同時に選ぶ。最終選別で合算するのはダブルス幅と縦境界の内側にある実測滞在で、最低25%を適用する。
- 3cam開発4本で、同じ選手ラベルの票が9割以上、カメラ・フレーム単位の票が各断片12以上の組を調べた。同じ側に各6実測フレーム以上、非重複で空白89フレーム以下、共通の骨長が3本以上の20組で、端の約0.2秒の位置中央値間の距離は中央値0.963 m、P95 3.298 m。骨長の対数比の絶対値の中央値は組間でP95 0.174、最大0.210。速度を両端で測れた15組の速度差は中央値1.626 m/s、P95 4.060 m/sだった。これらは#2444の再構成誤差を含む。4camの020・058で1フレーム差の水平最近傍距離のP95は0.042・0.051 mだが、3camでは支持カメラ切替により約0.9 mのずれが出るため、近接時の位置にも余裕を置いた。 [一段目の観測統計](../run-i2445-multiview-tracking/README.md#窓と選別規則の根拠)
- 連結の位置上限は `min(5 m, 0.95 m + 2.4 m/s × 時間差)`。速度による予測は両端から最大0.25秒。測れる両端の速度差にも費用を付け、欠測が長いほど速度差の重みを下げる。測定した3本以上の共通骨長を比較し、対数比の中央値0.35を上限とした。空き枠の核や追加の断片には少なくとも0.10秒、かつ実測の55%以上の同側領域内滞在を求める。6フレーム程度の候補にも利得を与え、0.35秒を過ぎてからは追加の滞在への加点を抑える。これらは連続性を判定する幾何の設定である。
- 0.4秒の第一段を固定し、追加の最大欠測を1.2、1.5、1.8、2.1、2.5秒で比較した。1.2秒の選別recallは63.53%。1.5秒以上では73.18%、射影IDF1は84.50%で揃った。1.5秒がこの結果に達した最短条件。000/000の正側を最長単独229フレームから統合後593フレームの実測に増やし、閾値253を満たした。 [開発用の上限比較](horizon.json)

## Meiji 3cam開発用4本

前後でカメラ・フレームごとの3D骨格射影を同じViTPoseと人手boxに照合した。時間窓のみを再実行し、初回記録と各クリップの両方式の集計が一致した。IDF1はカメラ・クリップ単位のID対応後に算出した。 [全クリップ・視点・連結の診断](meiji3.json)

| 対象 | 時間窓のみ IDF1 / switch / fragment | 枠統合後 IDF1 / switch / fragment |
| --- | --- | --- |
| 各カメラへの射影、選別全ID | 76.09% / 0 / 190 | 84.50% / 0 / 387 |
| 各カメラへの射影、選別前の全IDを選手ラベル上で評価 | 68.34% / 741 / 182 | 77.97% / 737 / 182 |
| 支持行へのID転記、選別全ID | 77.14% / 0 / 185 | 85.29% / 0 / 376 |
| 支持行へのID転記、選別前の全IDを選手ラベル上で評価 | 69.21% / 739 / 212 | 78.76% / 735 / 212 |

射影による選別precisionは99.94%から99.95%、recallは61.43%から73.18%。選手の採用12,629→15,044、非選手の採用7→7、未照合の採用20→44だった。支持行でのprecisionは99.95%から99.95%、recallは62.81%から74.38%。両側1人を選べたclipは3本から4本に増えた。

誤連結の指標として、各 `(camera, frame, person)` に新しく出たswitchを照合した。新規0件、解消4件で、000/000の1件と000/007の3件が解消した。採用後のfragmentは387件に増えた。以前は選別から外れていた実測区間が採点に入り、その間の欠測や他の断片との重なりも残る。骨格の補間行は採点対象外。たとえば002/013の正側には観測時間の重なる断片があり、今回の枠統合で追加された連結は0件だった。

実測の3cam採点は入力照合、#2444の復元、時間窓のみと統合後の採点を含め77.21秒。最大RSSは1,015,356 KiB。

対象3本は #2444 の固定済みViTPose計画の完了後に、開発用で固定した設定で採点する。#2444の共有queueにはすでに当該jobが投入されている。この更新時点は全9カメラの `complete.json` 待ちで、採点開始は0回。位置や骨長の設定は開発用で固定した。 [採点器・設定のdigest](reserved-protocol.json)・[前段の固定入力](../run-multiview-pose-link-recall-20261124/README.md#予約した未見3-clip)

```bash
bash knowledge/runs/run-i2445-multiview-tracking/reproduce.sh holdout
```

## 再現と比較ページへの受け渡し

```bash
bash knowledge/runs/run-i2445-multiview-tracking/reproduce.sh all
```

入力の置き場所は初回評価の環境変数と同じ。統合版の読戻し先は `outputs/i2445/integrated/meiji4/video_000/<clip>/scene.json`。段階2比較には `--tracks "$TRACK_OUTPUT/integrated/meiji4"` と、このrunの `meiji4.json` を `--tracking-record` に指定する。 `multiview_pose_tracks` v1の読込契約で開ける。時間窓のみの初回記録とstoreは従来と同じパスで再現できる。
