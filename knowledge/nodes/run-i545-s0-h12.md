## 考察 / Findings

### 要約
純共有端点（S=0/H=12）を base model で取得した参照 run。回転 10.85°、位置 0.664m で、#545 の split スイープおよび fully separate 端点より明確に悪い。特に位置が大きく崩れ、共有しきる構成は data-rich / full 学習でも不利。

### アーキテクチャ詳細
`multiview_axial_base`（`num_layers=12`）。split モデルは `num_task_layers<=0` を許容しないため、S=0/H=12 の純共有端点は base model で表現した。params は 77.645M で split の H+2S=12 系（77.845M）より約 0.2M 少ないため、厳密な param-match ではなく共有側の参照端点として扱う。学習条件は他の #545 run と同じく `chunked_multiview_sequence_bs8`、effective batch=8、`seq_len_range=[64,256]`、`canonical_rot`、early-stop OFF / 200ep。

### メトリクスの解釈
test 回転 mean 10.85°/median 8.34°、位置 mean 0.664m/median 0.599m。角度精度 `@15°=0.771`、位置精度 `@0.5m=0.428`。S=1/H=10 の 8.56°/0.385m からさらに悪化しており、共有側端点では特に位置が破綻に近い。

### アーキテクチャ⇄メトリクスの因果考察
共有 trunk のみでは rot/pose のタスク固有 readout を分離する容量が不足し、pose 側の空間的な補正を吸収しきれない可能性が高い（仮説）。S=1 ではまだ最低限の分岐 trunk が残るが、S=0 では完全共有となるため、位置誤差が 0.66m まで跳ねたと考えられる。

### 既存実験との比較
[[run-i545-s1-h10]]（8.56°/0.385m）より悪く、共有を厚くする単調な悪化傾向の端点になった。[[run-i545-s4-h4]]（8.23°/0.337m）や [[run-i545-s6-h0]]（8.96°/0.186m）と比べても、純共有はどちらの指標でも劣る。[[run-i539-ex10-chunked]]（early-stop あり, 15.84°/0.542m）より回転は良いが、位置は悪い。

### 次に有効な実験
純共有を主候補から外し、S>=1 の分岐 trunk を必須条件として扱う。共有寄りを深掘りするなら S=1/H=10 と S=2/H=8 の seed 再現性確認に限定し、位置改善の本筋は fully separate または balanced の head/loss 調整に置く。
