## 要約

#915 を分割して作った PR（#938/#939/#940）の tree で、**既定の `pipeline.yaml`** のまま Meiji `clip_000`（3 camera × 1010 frame）を最後まで処理した。
設定の変更は root path、device、ball を import するための `execution.ball_detection=load` の 3 つだけ。
Court（b863 + region search）、人物検出（DINO）、tracking、ViTPose、camera alignment、三角測量、GVHMR、身体配置、scene assembly はすべてモデル・アルゴリズムを実行した。
**import したのは次の 3 つで、いずれもモデルの推論結果ではない。**

- **ball**: 外注の `video_ball_annotation.v2` から、observed 点だけを観測として採用した。
- **court side**: import した ball だけを使い、4 通りの half-turn 仮説を幾何検定で確認した。
- **player association**: 旧手動対応と旧 GVHMR の bbox 軌跡を、現 track に照合して得た。

結果は status=ok。side は `[False, False, True]` で、最良の仮説の cost は 0.103、次点は 0.707 だった。scene は 2 人の軸を持つ。
関節 3D の有効 frame は [1010, 995]、root/SMPL は [1004, 995]、ball 3D は 987 frame。全 25 node の load-only 再開も完走した。

## 既存実験との比較

#915 の最終 run [run-scene-component-meiji-target2-20260925](000021-run-scene-component-meiji-target2-20260925.md) と、有効 frame 数・side 判定がすべて一致した。
変わった点は次の 3 つ。

- #915 の run は Court checkpoint と ROI margin を override していた。今回はそれらが既定値になっている。
- 人物対応の import は PLCS Re-ID の artifact と slot を経由しなくなった。bind された pose carrier に直接 player ID を付ける。
- store は clip の `annotations/` ではなく report 配下に作った。

人物対応の照合で、旧 GVHMR の各軸に対応する現 track は、median 距離 0.0 box で一意に決まった（次点は 0.86〜12.6 box）。
対象外として除外した track は 2 本で、理由は `person_confirmation.json` に記録してある。

- cam0 の track 4: 179 frame。最も近い旧軸でも 2.61 box 離れている。
- cam2 の track 5: 観測は 1 frame のみで、照合の対象外。

## 解釈と限界

これは既定設定とパイプライン構造の完走確認であり、side と人物対応のモデル精度は評価していない（どちらも import で埋めている）。
3D 精度についても、独立した基準との比較はしていない。
ball の 3D も外注注釈から得たもので、ball 検出器の性能は反映していない。
