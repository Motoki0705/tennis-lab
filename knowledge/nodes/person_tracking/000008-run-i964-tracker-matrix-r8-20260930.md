## 失敗の分布とcamera間対応

推薦候補のcam0 far IDF1は0.919944でbaseline0.741733から改善する一方、cam1 farは0.703617でbaseline0.937610を下回る。
全体のID switch/fragmentもbaseline5/8に対して14/31（baselineは丸ごと停止したcameraでswitch/fragmentを生まない点に注意）。外観を入れれば単純に断片化が減るという仮説は支持されない。
BoT候補は既知非選手を489/492 unit残し、video_001/clip_001のassociationは両encoderともambiguous_playersで停止した。

推薦候補のcamera間pair F1は0.967598、baselineは0.979717。ただし#933の分母はmatchできたunitに条件付きであり、
baselineはTP17,075、推薦候補は18,619。coverage差を無視してF1だけで優劣を決めない。
camera間encoderをCLIP→SOLIDERに替えても全candidateの最終ID対応は変わらなかった。
CLIPで校正した固定slope/centerのままの比較なのでSOLIDER専用calibration後の性能とは違う。
[人物→予測ID対応表](../../runs/run-i964-tracker-matrix-r8-20260930/correspondence.csv)は各clip/camera/encoderのbox数を記録する。

推薦候補で残る既知non-playerはclip_001 cam1のX1、963–965の3 unit。
run 6と同じ重複参照のケースで、選手BとX1の旧boxが重なるため真の誤人物選択と断定できない。
参照unitを事後除去せず、そのまま3残存・camera間FP6として数えた。
