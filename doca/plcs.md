# Player Localization in Court System (PLCS) 構想メモ

## 0. タスク概要

**目的**  
テニスコート座標系における **プレーヤーの位置と回転**を推定するモデル。

- **モデル名**: Player Localization in Court System (**PLCS**)
- **入力**:  
  - 画像から得られる **UV座標系のポーズ**
    - プレーヤーの2Dポーズ（キーポイント）
    - コートの2Dキーポイント  
  - 座標は **画像サイズで正規化された (u, v)** を使用  
    - `u = x / W, v = y / H`
- **出力**:  
  - **コート座標系**におけるプレーヤーの
    - 位置：\((x, y, z)\)
    - 回転（yaw など）
  - 位置は **コートの大きさで正規化**して扱う：
    - `x = X / HALF_DOUBLES_WIDTH`
    - `y = Y / HALF_LENGTH`
    - `z = Z / NET_HEIGHT_POST`

---

## 1. コート座標系の定義

### 1.1 基本設定

- **単位**: すべてメートル (m)
- **原点**:
  - `z = 0` の **コート面上**
  - **ネットの中心位置**を `(x=0, y=0, z=0)` とする
- **軸の向き**:
  - **x軸**: コートの左右方向  
    - `x > 0` : 右側  
    - `x < 0` : 左側
  - **y軸**: ネットに対して前後（ベースライン方向）
    - `y > 0` : far サイド（奥側コート）
    - `y < 0` : near サイド（手前コート）
  - **z軸**: 上下方向
    - `z = 0` : コート面
    - `z > 0` : 上方向（ネット・ボールの高さなど）

> この「ワールド座標 = コート座標」が、カメラ・プレーヤー・ボールなどすべての基準。

## 2. コートの寸法とライン位置

### 2.1 コート全体

- **コート長さ（ベースライン間）**  
  - `COURT_LENGTH = 23.77` m  
  - 半分: `HALF_LENGTH = 11.885` m  
    - far ベースライン: `y = +11.885`  
    - near ベースライン: `y = -11.885`
- **シングルス幅**
  - `SINGLES_WIDTH = 8.23` m  
  - 半分: `HALF_SINGLES_WIDTH = 4.115` m  
    - 左シングルスサイドライン:  `x = -4.115`  
    - 右シングルスサイドライン:  `x = +4.115`
- **ダブルス幅**
  - `DOUBLES_WIDTH = 10.97` m  
  - 半分: `HALF_DOUBLES_WIDTH = 5.485` m  
    - 左ダブルスサイドライン:  `x = -5.485`  
    - 右ダブルスサイドライン:  `x = +5.485`

### 2.2 サービスライン・T

- **サービスライン距離**
  - `SERVICE_LINE_DISTANCE = 6.40` m  
    - far サービスライン: `y = +6.40`  
    - near サービスライン: `y = -6.40`
- **サービスT**
  - far T: `(0, +6.40, 0)`  
  - near T: `(0, -6.40, 0)`

> サービスラインからベースラインまでの距離  
> `11.885 - 6.40 = 5.485` m で、ハーフダブルス幅と一致。

## 3. コート3Dキーポイント定義

> 以降、この 20 点の集合を **Court 3D Keypoints（略称: CourtKP20）** と呼ぶ。

### 3.1 インデックス定義（CourtKP20）

- **0..3: ダブルスコート四隅**
  - 0: far 左ダブルスコーナー `(-xd, +yB, 0)`
  - 1: far 右ダブルスコーナー `(+xd, +yB, 0)`
  - 2: near 左ダブルスコーナー `(-xd, -yB, 0)`
  - 3: near 右ダブルスコーナー `(+xd, -yB, 0)`  
    - ここで `xd = HALF_DOUBLES_WIDTH`, `yB = HALF_LENGTH`

- **4..7: シングルスコート四隅**
  - 4: far 左シングルスコーナー `(-xs, +yB, 0)`
  - 5: near 左シングルスコーナー `(-xs, -yB, 0)`
  - 6: far 右シングルスコーナー `(+xs, +yB, 0)`
  - 7: near 右シングルスコーナー `(+xs, -yB, 0)`  
    - `xs = HALF_SINGLES_WIDTH`

- **8..11: サービスライン端点**
  - 8: far サービスライン左端 `(-xs, +yS, 0)`
  - 9: far サービスライン右端 `(+xs, +yS, 0)`
  - 10: near サービスライン左端 `(-xs, -yS, 0)`
  - 11: near サービスライン右端 `(+xs, -yS, 0)`  
    - `yS = SERVICE_LINE_DISTANCE`

- **12,13: サービスT**
  - 12: far サービスT `(0, +yS, 0)`
  - 13: near サービスT `(0, -yS, 0)`

- **14: ネット中心（地面）**
  - `(0, 0, 0)`

- **15..18: ネットポスト（支柱）**
  - ダブルスサイドラインから **外側に 0.914m** (`NET_POST_OFFSET_X`)  
    - 左ポスト x 座標: `x_post_L = -(xd + 0.914)`  
    - 右ポスト x 座標: `x_post_R = +(xd + 0.914)`
  - 15: 左ポスト根元 `(x_post_L, 0, 0)`
  - 16: 左ポスト頂点 `(x_post_L, 0, NET_HEIGHT_POST)`
  - 17: 右ポスト根元 `(x_post_R, 0, 0)`
  - 18: 右ポスト頂点 `(x_post_R, 0, NET_HEIGHT_POST)`

- **19: センターストラップ頂点**
  - `(0, 0, NET_HEIGHT_CENTER)`

### 3.2 ネット高さ

- ネット中央: `NET_HEIGHT_CENTER = 0.914` m  
- ポスト高さ: `NET_HEIGHT_POST = 1.07` m

## 4. COCO 2Dキーポイント定義

> 以降、プレーヤーの 2D ポーズは **COCO 17 Keypoints** を前提とし、  
> この 17 点の集合を **Human 2D Keypoints（略称: HumanKP17）** と呼ぶ。

### 4.1 インデックス定義（HumanKP17）

COCO の標準スケルトンに従い、インデックスとキーポイント名を次のように定義する：

- 0: `nose`
- 1: `left_eye`
- 2: `right_eye`
- 3: `left_ear`
- 4: `right_ear`
- 5: `left_shoulder`
- 6: `right_shoulder`
- 7: `left_elbow`
- 8: `right_elbow`
- 9: `left_wrist`
- 10: `right_wrist`
- 11: `left_hip`
- 12: `right_hip`
- 13: `left_knee`
- 14: `right_knee`
- 15: `left_ankle`
- 16: `right_ankle`

### 4.2 座標系と正規化

- 各キーポイントは画像座標 `(x, y)` を持ち、
- モデル入力では **画像サイズで正規化**された `(u, v)` を利用する：
  - `u = x / W`
  - `v = y / H`
- 1フレームあたりの HumanKP17 テンソル形状は：
  - `[17, 2]` （座標のみ）  
  - または `[17, 3]` （座標 + 可視フラグ）等を拡張で検討。

## 5. フェンス（ランオフ）領域とシミュレーション空間

コート周辺にランオフ＋フェンスを含めた **シミュレーションの有効範囲**を定義。

- **ランオフ（クリアランス）**
  - ベースライン後: `BASELINE_CLEAR = 6.40` m
  - サイドライン外側: `SIDELINE_CLEAR = 3.66` m
- **フェンス高さ**
  - `FENCE_HEIGHT = 3.0` m

そこから求まるシミュレーション空間の境界:

- `X_MIN = -(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = -9.145`
- `X_MAX = +(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = +9.145`
- `Y_MIN = -(HALF_LENGTH + BASELINE_CLEAR) = -18.285`
- `Y_MAX = +(HALF_LENGTH + BASELINE_CLEAR) = +18.285`

つまり、シミュレーション上のワールド範囲はおおよそ:

- 左右: `x ∈ [-9.145, 9.145]`
- 前後: `y ∈ [-18.285, 18.285]`
- 上方向（フェンス頂部）: `z ≈ 3.0`

## 6. データセットとシミュレーション設計

### 6.1 モーションソース: AMASS

- AMASS から `poses (T×156)`, `trans (T×3)` を利用する。
- 各シーケンスについて:
  - `trans` → **コート座標系におけるプレーヤー位置 GT** として利用。
  - `poses` + SMPL-H → 3Dジョイントを生成し、仮想カメラから投影して **UV座標のポーズ** を作る。

### 6.2 シーン構成（プレーヤーの動き）

1. **AMASS からシーン（モーションシーケンス）を数個抽出**。
2. 各シーンの長さ（フレーム数）を比較し、  
   **最短の長さに合わせてトリム**する。
   - 長いシーンは末尾フレームを切り捨てる。
3. 各シーンごとに
   - コート上の初期位置（`(x0, y0)`）
   - 初期向き（yaw）
   をランダムにサンプリングして与える。
4. 上記の初期条件でシミュレーションを開始し、  
   プレーヤーがコート上を移動する様子を **一括で再生**する。

> 最終的には、複数プレーヤー / 複数モーションを同時に置く拡張も可能。

## 7. カメラ設定とサンプリング

### 7.1 カメラ位置のサンプリング範囲（フェンス周辺＋少し内＋少し外）

カメラは「コートを囲むフェンスの周辺」に配置することを想定する。  
具体的には、**フェンス線上を基準にして、そこから少し内側・少し外側にオフセットした領域**からランダムサンプリングする。

#### フェンス矩形の定義（おさらい）

- フェンスで囲まれたシミュレーション空間の境界は：

  - `X_MIN = -(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = -9.145`
  - `X_MAX = +(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = +9.145`
  - `Y_MIN = -(HALF_LENGTH + BASELINE_CLEAR) = -18.285`
  - `Y_MAX = +(HALF_LENGTH + BASELINE_CLEAR) = +18.285`

  となるので、フェンス矩形は

  - 左フェンス:  `x = X_MIN`
  - 右フェンス:  `x = X_MAX`
  - 手前フェンス:`y = Y_MIN`
  - 奥フェンス:  `y = Y_MAX`

#### サンプリング方針

1. **どのフェンス側にカメラを置くか**をランダムに選ぶ  
   - 候補: `{ left, right, near, far }`  
   - 例: 一様に 1/4 ずつ選択。

2. 選ばれた側の **フェンス線上の位置**を一様サンプリング  
   - 左/右フェンスの場合:  
     - `y ∈ [Y_MIN, Y_MAX]` を一様サンプリング  
     - `x` は `X_MIN` または `X_MAX` に固定
   - near/far フェンスの場合:  
     - `x ∈ [X_MIN, X_MAX]` を一様サンプリング  
     - `y` は `Y_MIN` または `Y_MAX` に固定

3. フェンス線からの **内外オフセット**をサンプリング  
   - フェンスからの距離 `r` を  
     - `r ∈ [-r_in, +r_out]` から一様サンプリング  
     - 例: `r_in = 1.0` m（内側最大1m）、`r_out = 2.0` m（外側最大2m）
   - サイドごとの進め方:
     - 左フェンス (`x = X_MIN`):  
       - 法線は **+x 方向**が内側 →  
         `x_cam = X_MIN + r`  （r<0 でフェンス外、r>0 で内側）
     - 右フェンス (`x = X_MAX`):  
       - 法線は **-x 方向**が内側 →  
         `x_cam = X_MAX - r`
     - near フェンス (`y = Y_MIN`):  
       - 法線は **+y 方向**が内側 →  
         `y_cam = Y_MIN + r`
     - far フェンス (`y = Y_MAX`):  
       - 法線は **-y 方向**が内側 →  
         `y_cam = Y_MAX - r`

4. 高さ方向（z）のサンプリング  
   - カメラ高さはフェンスより少し高いレンジからサンプル：
     - `z_cam ∈ [3.0, 5.0]`  
       （`FENCE_HEIGHT = 3.0` m を基準に、「フェンスの少し上〜さらに高い位置」）

#### 直感的な意味

- カメラは常に **「フェンスの近く」** に配置される。
- `r > 0` のときは **フェンスの内側（コート側）** に 〜1m 入った位置。
- `r < 0` のときは **フェンスの外側** に最大 2m 出た位置。
- これにより、  
  「フェンスのすぐ外／フェンスの真上／フェンスから少し内側」のような、  
  実際の観客席・通路・スタンドに近いカメラ配置を表現できる。

### 7.2 マルチカメラ撮影

- 1つのシーンにつき、**複数カメラ**を上記範囲からランダムにサンプリング。
- 各カメラについて
  - カメラの位置をサンプル
  - カメラの向きは「原点（ネット中央付近）」付近を向くように設定し、  
    そこに小さなノイズ（揺らぎ）を加える。
- これにより、テニス中継や観客席などに近い多様な視点を再現。

## 8. 生成するデータ（目標）

シミュレーションのゴールは、各フレーム・各カメラに対して：

- **3D情報（コート座標系）**
  - プレーヤー root 位置
    - コートの大きさで正規化された `(x, y, z)`
  - プレーヤーの向き（回転, yaw）

- **2D情報（UV座標系）**
  - カメラごとの **プレーヤー2Dポーズ**（HumanKP17）
    - COCO の 17 keypoints（HumanKP17）
    - 画像サイズで正規化された `(u, v)`
  - カメラごとの **コート3Dキーポイントの 2D投影** 
    - Court 3D Keypoints（CourtKP20）に対応する 20 keypoints
    - こちらも `(u, v)` 正規化座標

- **PLCS モデルの教師ペア**
  - 入力:
    - `UV` 座標系のプレーヤーポーズ（HumanKP17, 正規化）
    - `UV` 座標系のコートポーズ（CourtKP20 の 2D投影, 正規化）
  - 出力:
    - コート座標系におけるプレーヤー位置 \((x, y, z)\)（コートサイズで正規化）
    - プレーヤーの向き（回転, yaw）
