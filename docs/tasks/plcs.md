# Player Localization in Court System (PLCS)

## 0. タスク概要

**目的**
テニスコート座標系における **プレーヤーの位置と回転**を推定するモデル。

- **モデル名**: Player Localization in Court System (**PLCS**)
- **入力**:
  - 画像から得られる **UV座標系のポーズ**
    - プレーヤーの2Dポーズ（キーポイント）
    - コートの2Dキーポイント
  - 座標は **画像サイズで正規化された (u, v)** を使用
    - `u = x / W, v = y / H`
  - シーケンス版モデルでは、これらの2Dキーポイントの**時間方向の列** \(`(T, 17, 2)`, `(T, 20, 2)`\) をそのまま入力として扱い、時系列情報も活用する。
- **出力**:
  - **コート座標系**におけるプレーヤーの
    - 位置：\((x, y, z)\)
    - 回転（yaw など）
  - 位置は **コートの大きさで正規化**して扱う：
    - `x = X / HALF_DOUBLES_WIDTH`
    - `y = Y / HALF_LENGTH`
    - `z = Z / NET_HEIGHT_POST`
  - シーケンス版モデルでは、各フレームの位置・回転の**時系列** \(`(T, 3)`, `(T, 2)`\) をまとめて推定し、プレーヤーの動き全体を捉える。

---

## 1. コート座標系の定義

### 1.1 基本設定

- **単位**: すべてメートル (m)
- **原点**:
  - `z = 0` の **コート面上**
  - **ネットの中心位置**を `(x=0, y=0, z=0)` とする
- **軸の向き**:
  - **x軸**: コートの左右方向
    - `x > 0` : 右側
    - `x < 0` : 左側
  - **y軸**: ネットに対して前後（ベースライン方向）
    - `y > 0` : far サイド（奥側コート）
    - `y < 0` : near サイド（手前コート）
  - **z軸**: 上下方向
    - `z = 0` : コート面
    - `z > 0` : 上方向（ネット・ボールの高さなど）

> この「ワールド座標 = コート座標」が、カメラ・プレーヤー・ボールなどすべての基準。

## 4. COCO 2Dキーポイント定義

> 以降、プレーヤーの 2D ポーズは **COCO 17 Keypoints** を前提とし、
> この 17 点の集合を **Human 2D Keypoints（略称: HumanKP17）** と呼ぶ。

### 4.1 インデックス定義（HumanKP17）

COCO の標準スケルトンに従い、インデックスとキーポイント名を次のように定義する：

- 0: `nose`
- 1: `left_eye`
- 2: `right_eye`
- 3: `left_ear`
- 4: `right_ear`
- 5: `left_shoulder`
- 6: `right_shoulder`
- 7: `left_elbow`
- 8: `right_elbow`
- 9: `left_wrist`
- 10: `right_wrist`
- 11: `left_hip`
- 12: `right_hip`
- 13: `left_knee`
- 14: `right_knee`
- 15: `left_ankle`
- 16: `right_ankle`

### 4.2 座標系と正規化

- 各キーポイントは画像座標 `(x, y)` を持ち、
- モデル入力では **画像サイズで正規化**された `(u, v)` を利用する：
  - `u = x / W`
  - `v = y / H`
- 1フレームあたりの HumanKP17 テンソル形状は：
  - `[17, 2]` （座標のみ）
  - または `[17, 3]` （座標 + 可視フラグ）等を拡張で検討。

## 5. フェンス（ランオフ）領域とシミュレーション空間

コート周辺にランオフ＋フェンスを含めた **シミュレーションの有効範囲**を定義。

- **ランオフ（クリアランス）**
  - ベースライン後: `BASELINE_CLEAR = 6.40` m
  - サイドライン外側: `SIDELINE_CLEAR = 3.66` m
- **フェンス高さ**
  - `FENCE_HEIGHT = 3.0` m

そこから求まるシミュレーション空間の境界:

- `X_MIN = -(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = -9.145`
- `X_MAX = +(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = +9.145`
- `Y_MIN = -(HALF_LENGTH + BASELINE_CLEAR) = -18.285`
- `Y_MAX = +(HALF_LENGTH + BASELINE_CLEAR) = +18.285`

つまり、シミュレーション上のワールド範囲はおおよそ:

- 左右: `x ∈ [-9.145, 9.145]`
- 前後: `y ∈ [-18.285, 18.285]`
- 上方向（フェンス頂部）: `z ≈ 3.0`

## 6. データセットとシミュレーション設計

### 6.1 モーションソース: AMASS/ACCAD

- AMASS/ACCAD から `poses (T×156)`, `trans (T×3)`, `betas`, `gender` を利用する。
- 各シーケンスについて:
  - `trans` → **コート座標系におけるプレーヤー pelvis 位置** として利用。
  - `poses` + SMPL-H → 3Dジョイント（73点）を生成。
  - SMPL-Hジョイント → COCO17にマッピングして **HumanKP17** を得る。

### 6.2 座標系と回転の表現

#### 回転（yaw）の内部表現

- **保存形式**: `(sin(yaw), cos(yaw))`
  - `atan2(sin, cos)` で角度を正確に復元可能
  - 単位円上のベクトルとして扱える

#### ローカル前方とワールド前方

- **ローカル前方**: `[0, 1, 0]` (SMPL-Hの+Y方向)
- **ワールド前方**: yaw回転後の方向ベクトル
  - 回転行列 `R(yaw)` を適用すると:
    ```
    R(yaw) @ [0, 1, 0] = [-sin(yaw), cos(yaw), 0]
    ```
  - つまり、前方ベクトルは `(-sin(yaw), cos(yaw))` で表される

> **注意**: 保存形式 `(sin, cos)` と前方ベクトル `(-sin, cos)` は異なる。
> 損失計算では `(sin, cos)` を使用し、可視化時に前方ベクトルに変換する。

### 6.3 シーン構成

1. **AMASS/ACCAD からモーションシーケンスをサンプリング**。
   - カテゴリ（running, walking, general, etc.）による重み付けサンプリング。
2. 各シーンごとに:
   - コート上の初期位置 `(x0, y0)` をランダムサンプリング（シングルスコート内）
   - 初期向き `yaw` をランダムサンプリング
3. モーションを初期位置・向きに変換:
   - XY座標のみオフセット（Z座標は pelvis 高さを保持）
   - yaw回転を適用
4. 複数カメラからの2D投影を計算。

### 6.4 中間表現フォーマット（NPZ）

生成されたシーンは NPZ 形式で保存される：

```
scene_XXXXXX.npz
├── meta          # メタデータ（scene_id, motion_source, fps, etc.）
├── position      # (T, 3) 正規化された位置
├── rotation      # (T, 2) sin/cos形式のyaw
├── canonical_pose_3d  # (T, 73, 3) pelvis中心のローカル3Dポーズ
├── num_cameras   # カメラ数
└── cam_N_*       # 各カメラのデータ
    ├── params           # カメラパラメータ
    ├── human_kp_uv      # (T, 17, 2) 人物キーポイントUV
    ├── court_kp_uv      # (T, 20, 2) コートキーポイントUV
    ├── human_kp_visible # (T, 17) 可視フラグ
    └── court_kp_visible # (T, 20) 可視フラグ
```

## 7. カメラ設定とサンプリング

### 7.1 カメラ位置のサンプリング範囲（フェンス周辺＋少し内＋少し外）

カメラは「コートを囲むフェンスの周辺」に配置することを想定する。
具体的には、**フェンス線上を基準にして、そこから少し内側・少し外側にオフセットした領域**からランダムサンプリングする。

#### フェンス矩形の定義（おさらい）

- フェンスで囲まれたシミュレーション空間の境界は：

  - `X_MIN = -(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = -9.145`
  - `X_MAX = +(HALF_DOUBLES_WIDTH + SIDELINE_CLEAR) = +9.145`
  - `Y_MIN = -(HALF_LENGTH + BASELINE_CLEAR) = -18.285`
  - `Y_MAX = +(HALF_LENGTH + BASELINE_CLEAR) = +18.285`

  となるので、フェンス矩形は

  - 左フェンス:  `x = X_MIN`
  - 右フェンス:  `x = X_MAX`
  - 手前フェンス:`y = Y_MIN`
  - 奥フェンス:  `y = Y_MAX`

#### サンプリング方針

1. **どのフェンス側にカメラを置くか**をランダムに選ぶ
   - 候補: `{ left, right, near, far }`
   - 例: 一様に 1/4 ずつ選択。

2. 選ばれた側の **フェンス線上の位置**を一様サンプリング
   - 左/右フェンスの場合:
     - `y ∈ [Y_MIN, Y_MAX]` を一様サンプリング
     - `x` は `X_MIN` または `X_MAX` に固定
   - near/far フェンスの場合:
     - `x ∈ [X_MIN, X_MAX]` を一様サンプリング
     - `y` は `Y_MIN` または `Y_MAX` に固定

3. フェンス線からの **内外オフセット**をサンプリング
   - フェンスからの距離 `r` を
     - `r ∈ [-r_in, +r_out]` から一様サンプリング
     - 例: `r_in = 1.0` m（内側最大1m）、`r_out = 2.0` m（外側最大2m）
   - サイドごとの進め方:
     - 左フェンス (`x = X_MIN`):
       - 法線は **+x 方向**が内側 →
         `x_cam = X_MIN + r`  （r<0 でフェンス外、r>0 で内側）
     - 右フェンス (`x = X_MAX`):
       - 法線は **-x 方向**が内側 →
         `x_cam = X_MAX - r`
     - near フェンス (`y = Y_MIN`):
       - 法線は **+y 方向**が内側 →
         `y_cam = Y_MIN + r`
     - far フェンス (`y = Y_MAX`):
       - 法線は **-y 方向**が内側 →
         `y_cam = Y_MAX - r`

4. 高さ方向（z）のサンプリング
   - カメラ高さはフェンスより少し高いレンジからサンプル：
     - `z_cam ∈ [3.0, 5.0]`
       （`FENCE_HEIGHT = 3.0` m を基準に、「フェンスの少し上〜さらに高い位置」）

#### 直感的な意味

- カメラは常に **「フェンスの近く」** に配置される。
- `r > 0` のときは **フェンスの内側（コート側）** に 〜1m 入った位置。
- `r < 0` のときは **フェンスの外側** に最大 2m 出た位置。
- これにより、
  「フェンスのすぐ外／フェンスの真上／フェンスから少し内側」のような、
  実際の観客席・通路・スタンドに近いカメラ配置を表現できる。

### 7.2 マルチカメラ撮影

- 1つのシーンにつき、**複数カメラ**を上記範囲からランダムにサンプリング。
- 各カメラについて
  - カメラの位置をサンプル
  - カメラの向きは「原点（ネット中央付近）」付近を向くように設定し、
    そこに小さなノイズ（揺らぎ）を加える。
- これにより、テニス中継や観客席などに近い多様な視点を再現。

## 8. 生成するデータ（目標）

シミュレーションのゴールは、各フレーム・各カメラに対して：

- **3D情報（コート座標系）**
  - プレーヤー pelvis 位置
    - コートの大きさで正規化された `(x, y, z)`
    - `x = X / HALF_DOUBLES_WIDTH`, `y = Y / HALF_LENGTH`, `z = Z / NET_HEIGHT_POST`
  - プレーヤーの向き（yaw）
    - `(sin(yaw), cos(yaw))` 形式で保存

- **2D情報（UV座標系）**
  - カメラごとの **プレーヤー2Dポーズ**（HumanKP17）
    - COCO の 17 keypoints（HumanKP17）
    - 画像サイズで正規化された `(u, v)` ∈ [0, 1]
  - カメラごとの **コート3Dキーポイントの 2D投影**
    - Court 3D Keypoints（CourtKP20）に対応する 20 keypoints
    - こちらも `(u, v)` 正規化座標

- **PLCS モデルの教師ペア**
  - 入力:
    - `UV` 座標系のプレーヤーポーズ（HumanKP17, 正規化）: `(17, 2)` → flatten → `(34,)`
    - `UV` 座標系のコートポーズ（CourtKP20 の 2D投影, 正規化）: `(20, 2)` → flatten → `(40,)`
    - 可視フラグ（オプション）: human `(17,)`, court `(20,)`
  - 出力:
    - コート座標系におけるプレーヤー位置 `(x, y, z)`（コートサイズで正規化）
    - プレーヤーの向き `(sin(yaw), cos(yaw))`

## 9. 評価指標

### 9.1 誤差指標

| 指標 | 説明 |
|-----|------|
| `position_error_m` | 位置誤差（メートル、ユークリッド距離） |
| `x_error_m`, `y_error_m`, `z_error_m` | 各軸の位置誤差 |
| `angular_error_deg` | 角度誤差（度） |

### 9.2 精度指標

| 指標 | 説明 | デフォルト閾値 |
|-----|------|--------------|
| `position_accuracy` | 位置が閾値内の割合 | 0.5m |
| `position_accuracy_1m` | 位置が1m以内の割合 | 1.0m |
| `position_accuracy_2m` | 位置が2m以内の割合 | 2.0m |
| `angle_accuracy` | 角度が閾値内の割合 | 15° |
| `angle_accuracy_10deg` | 角度が10°以内の割合 | 10° |
| `angle_accuracy_30deg` | 角度が30°以内の割合 | 30° |
