# Ball Localization in Court System (BLCS)

## 0. タスク概要

**BLCS** は、「画像中で観測されたボールの 2D 軌道」から
**テニスコート座標系でのボールの 3D 軌道**を復元するためのタスク／モデル群である。

- **モデル名**: Ball Localization in Court System (**BLCS**)

- **入力（1シーン・1カメラ）**:
  - ボールの 2D 軌道（UV 座標系）
    - 各フレームのボール中心の 2D 位置列 \((u_t, v_t)\),  時系列長 \(T\)
    - 画像サイズで正規化された `(u, v)` を用いる
      - `u = x / W`, `v = y / H`
  - コートの 2D キーポイント（UV 座標系）
    - そのシーン・カメラに対して **固定の CourtKP20 投影**（PLCS で定義済み）

- **出力**:
  - コート座標系におけるボールの 3D 軌道 \((X_t, Y_t, Z_t)\)（長さ \(T\)）
  - 学習時には、以下の **正規化座標**を扱う：
    - `x = X / HALF_DOUBLES_WIDTH`
    - `y = Y / HALF_LENGTH`
    - `z = Z / NET_HEIGHT_POST`

> 1シーンは、**最大 2 ショットからなるラリー**を含む。
> t = 0 で 1ショット目が打ち出され、
> その 1バウンド目〜2バウンド目（またはフェンス直撃）の間で 1 回だけリターンが行われ、
> 2ショット目の 1バウンド目〜2バウンド目（またはフェンス直撃）までを含んだ軌道がシーン全体となる。

---

## 1. 座標系とコート定義（PLCS 参照）

BLCS は PLCS と同じコート座標系を用いる。

- **原点**: ネット中心のコート面 `(x=0, y=0, z=0)`
- **軸**:
  - x軸: 左右方向（`x>0` が右）
  - y軸: ネットに対して前後（`y>0` が far サイド）
  - z軸: 高さ（`z=0` がコート面）

- コート寸法・CourtKP20（20 個の 3D キーポイント）・
  フェンス矩形 `[X_MIN, X_MAX] × [Y_MIN, Y_MAX]` は PLCS の定義をそのまま使用する。

> 以降、コート座標系でのボール位置 \(\mathbf{p} = (X, Y, Z)\) を「ワールド座標」と呼ぶ。

## 2. ボール状態と物理モデル

### 2.1 状態変数

1 ショット \(s \in \{1,2\}\) について、離散時刻 \( t = 0, 1, ..., T_\text{sim}^{(s)} \) を考える。

- 位置:
  \[
  \mathbf{p}_t^{(s)} = (X_t^{(s)}, Y_t^{(s)}, Z_t^{(s)}) \in \mathbb{R}^3
  \]
- 速度:
  \[
  \mathbf{v}_t^{(s)} = (V_{x,t}^{(s)}, V_{y,t}^{(s)}, V_{z,t}^{(s)}) \in \mathbb{R}^3
  \]
- 角速度（スピン）:
  \[
  \boldsymbol{\omega}_0^{(s)} = (\omega_x^{(s)}, \omega_y^{(s)}, \omega_z^{(s)}) \in \mathbb{R}^3
  \]
  - シンプル化のため、「ショット中はスピン一定（\(\boldsymbol{\omega}_t^{(s)} = \boldsymbol{\omega}_0^{(s)}\)）」とする。

時間刻みは `dt`（例: `dt = 1/240 s`）とし、内部シミュレーションはこのレートで進める。

### 2.2 力のモデル

ボールに働く力として、以下を考える。

- **重力**:
  \[
  \mathbf{a}_g = (0, 0, -g), \quad g = 9.81\,\mathrm{m/s^2}
  \]

- **空気抵抗（ドラッグ）**: 速度二乗ドラッグの簡易モデル
  - 係数 \(k_d > 0\)
  - 速度ベクトル \(\mathbf{v}\) に対して
    \[
    \mathbf{a}_d = - k_d \, \|\mathbf{v}\| \, \mathbf{v}
    \]

- **スピンによる揚力（マグヌス効果）**:
  - 係数 \(k_m > 0\)
  - 角速度 \(\boldsymbol{\omega}\) と速度 \(\mathbf{v}\) から
    \[
    \mathbf{a}_m = k_m \, (\boldsymbol{\omega} \times \mathbf{v})
    \]

したがって、**空中にあるとき** の加速度は

\[
\mathbf{a} = \mathbf{a}_g + \mathbf{a}_d + \mathbf{a}_m
= (0, 0, -g) - k_d \|\mathbf{v}\|\mathbf{v} + k_m (\boldsymbol{\omega} \times \mathbf{v})
\]

とする（ボール質量 \(m\) は \(k_d, k_m\) に吸収）。

### 2.3 数値積分（semi-implicit Euler）

1 ステップの更新は次のように行う：

1. 加速度の計算:
   \[
   \mathbf{a}_t^{(s)} = f(\mathbf{p}_t^{(s)}, \mathbf{v}_t^{(s)}, \boldsymbol{\omega}_0^{(s)})
   \]
2. 速度の更新:
   \[
   \mathbf{v}_{t+1}^{(s)} = \mathbf{v}_t^{(s)} + \mathbf{a}_t^{(s)} \, dt
   \]
3. 位置の更新:
   \[
   \mathbf{p}_{t+1}^{(s)} = \mathbf{p}_t^{(s)} + \mathbf{v}_{t+1}^{(s)} \, dt
   \]

衝突イベント（バウンド・ネット・フェンスなど）がある場合は、
速度更新のあとに衝突処理を挟み、その結果で位置を補正する。

## 3. 衝突モデル（バウンド・ネット・フェンス）

### 3.1 コート面とのバウンド

コート面は `Z = 0` の平面とし、
`Z` 成分が 0 を下回ったタイミングでバウンドが発生するとみなす。

**バウンド検出条件（簡易）**:

- `Z_t > 0` かつ `Z_{t+1} <= 0`
- かつ `V_{z,t+1} < 0`（下向きに落ちている）

バウンド時の反射は、法線方向（z軸）と接線方向（x,y）に分ける。

- 法線方向（高さ）:
  \[
  V_{z,t+1}' = - e_z \, V_{z,t+1}
  \]
  - \(e_z\): 反発係数（例: 0.6〜0.8）

- 接線方向（x,y）:
  \[
  V_{x,t+1}' = (1 - \mu) V_{x,t+1}, \quad
  V_{y,t+1}' = (1 - \mu) V_{y,t+1}
  \]
  - \(\mu\): 摩擦係数（例: 0.05〜0.2）

速度を更新したうえで、「地面上」にクリップする：

\[
Z_{t+1}' = 0
\]

このときのインデックスを **バウンドイベント時刻**として記録する。

- 各ショット \(s\) について
  - 1バウンド目時刻: `t_b1^{(s)}`
  - 2バウンド目時刻: `t_b2^{(s)}`（存在する場合）

### 3.2 ネットとの衝突（減速のみ・reject しない）

ネットは `y = 0` の平面＋高さ制約として扱う。

BLCS では、ネットにかかったショットもデータセットに含めるため、
**ネット衝突は reject の条件にはしない。**
代わりに、簡易な減速モデルだけ適用する。

- 判定:
  - 時刻 t から t+1 の間で `y` の符号が変わる（ネットを跨いでいる）
  - かつ、その区間でのボール高さがネット高さ付近（例: `Z < NET_HEIGHT_POST`）

- モデル（例）:
  - ネットに当たったとみなしたタイミングで速度を減衰させる：
    \[
    \mathbf{v}_{t+1}' = \alpha_\text{net} \, \mathbf{v}_{t+1}, \quad 0 < \alpha_\text{net} < 1
    \]
  - 必要なら z 成分をより強く減衰させるなどの調整を行う。

その後は通常通りシミュレーションを継続し、
「ネットしてから相手コートに 1バウンド → 2バウンド」する軌道も生成対象とする。

### 3.3 フェンス・コート外

PLCS で定義したフェンス矩形 `[X_MIN, X_MAX] × [Y_MIN, Y_MAX]` を超えた場合、
またはフェンス面（x または y 方向の境界）に到達した場合：

- その時刻を **フェンス接触時刻** `t_fence^{(s)}` として記録する。
- 以降のシミュレーションはそのショットについては不要なので打ち切る。

### 3.4 reject 条件のまとめ

1ショット目・2ショット目ともに、
**「ショットがコート外」の場合のみ reject** とする。

ここで「ショットがコート外」とは、

- そのショットの **1バウンド目が存在しない**、または
- 1バウンド目の位置 \(\mathbf{p}_{b1}^{(s)}\) が、対象サイドのシングルスエリア外

である場合を指す。

ネット接触は reject の条件には入れない。

## 4. 初期条件サンプリングと 1ショット生成

まずは 1ショット（単独）の初期条件 \((\mathbf{p}_0, \mathbf{v}_0, \boldsymbol{\omega}_0)\) をサンプリングし、
**物理シミュレーション → 成否判定 → 採用 or 破棄** の流れでショットを生成する。

ここでの「成否」は、**1バウンド目が相手コート内かどうか**で決める。
ネットは成否に影響しない（3.2節）。

### 4.1 初期位置のサンプリング（例: near サイドのストローク）

ストロークで near から far に打つ例：

- x 方向（左右）:
  \[
  X_0 \sim \mathcal{U}(-4.0, 4.0) \quad (\text{シングルス幅付近})
  \]
- y 方向（前後）:
  - near サイドのベースライン付近：
    \[
    Y_0 \sim \mathcal{U}(-11.5, -10.0)
    \]
- z 方向（高さ）:
  \[
  Z_0 \sim \mathcal{U}(0.8, 1.4) \quad (\text{打点高さ})
  \]

（サーブ・ロブなどは別の分布を定義しても良い。）

### 4.2 初期速度と方向

初期速度 \(\mathbf{v}_0\) は、「大きさ + 方向」で定義する。

1. 速度の大きさ:
   \[
   \|\mathbf{v}_0\| \sim \mathcal{U}(v_{\min}, v_{\max}),
   \quad \text{例: } v_{\min} = 15,\, v_{\max} = 35\,\mathrm{m/s}
   \]

2. 水平面内の向き（方位角）\(\phi\):
   - near → far に打つとき、`Y` 正方向を中心とし、
     \[
     \phi \sim \mathcal{U}(-30^\circ, 30^\circ)
     \]

3. 上下方向の仰角 \(\theta\):
   - ストローク用：
     \[
     \theta \sim \mathcal{U}(5^\circ, 25^\circ)
     \]

これらから、コート座標系に合わせて \(\mathbf{v}_0 = (V_{x,0}, V_{y,0}, V_{z,0})\) を構成する。

### 4.3 初期スピン

スピンも初期条件として有効にし、物理モデルに組み込む。

- ショットタイプごとのスピンモード（例）:
  - トップスピン: \(\omega_y < 0\)
  - バックスピン: \(\omega_y > 0\)
  - フラット: \(\boldsymbol{\omega} \approx 0\)

例: トップスピン系ストローク

\[
\omega_x \sim \mathcal{U}(-20, 20),\quad
\omega_y \sim \mathcal{U}(-80, -40),\quad
\omega_z \sim \mathcal{U}(-20, 20)
\]

（単位や具体値は後でチューニング可能なハイパーパラメータとする。）

### 4.4 成功条件（accept-reject）

サンプリングした \((\mathbf{p}_0, \mathbf{v}_0, \boldsymbol{\omega}_0)\) について
物理シミュレーションを行い、**1バウンド目が相手コート内かどうか**で成否を判定する。

near → far に打つ場合の例：

- 1バウンド目の位置 \(\mathbf{p}_{b1} = (X_{b1}, Y_{b1}, 0)\) について、
  - `y > 0`（far サイド）
  - `|x| <= HALF_SINGLES_WIDTH`
  - `0 < y <= HALF_LENGTH`

をすべて満たすとき、「インプレー」として成功と見なし、そのショットを採用する。

- ネットに当たってもよい（3.2 節）。
- 1バウンド目が存在しない（フェンスに当たる／シミュレーション範囲外まで行く）場合も reject。

> この accept-reject を 1ショット目・2ショット目両方に対して行う。
> reject されるのは、**1ショット目または 2ショット目の 1バウンド目がコート外の場合のみ**である。

## 5. 2ショットラリーのシミュレーション（シーン全体）

1 シーンは、**最大 2 ショットからなるラリー**を含む。

タイムラインは 1 本で、t=0 から始まり、
1ショット目 → リターン → 2ショット目 → 終了 の流れで進む。

### 5.1 t = 0（シーン開始）

- シーンの開始は常に **t = 0** とし、
- これは **1ショット目の初期条件時刻**に対応する。

この時点での状態を \((\mathbf{p}_0^{(1)}, \mathbf{v}_0^{(1)}, \boldsymbol{\omega}_0^{(1)})\) とする。

### 5.2 1ショット目のシミュレーション（打ち出し側 → 相手コート）

1ショット目について、4 章で述べた初期条件を用いてシミュレーションし、

- 1バウンド目時刻: `t_b1^{(1)}`
- 2バウンド目時刻: `t_b2^{(1)}`（存在する場合）
- フェンス接触時刻: `t_fence^{(1)}`（存在する場合）

を求める。

このとき、4.4 節の成功条件を満たさない場合（1バウンド目がコート外）は
このラリー全体を破棄し、最初からやり直す。

### 5.3 リターン打球時刻 t_hit のサンプリング

**リターン（2ショット目）は 1 回のみ**とし、
「1ショット目の 1バウンド目から 2バウンド目（またはフェンス直撃）の間」に行われる、という前提を置く。

1. まず「1ショット目が自然に飛んだ場合」の
   2バウンド目またはフェンス時刻を求める（理論上の値）：

   \[
   t_\text{stop}^{(1)} = \min\Bigl(
      t_{b2}^{(1)}\ \text{(あれば)},
      t_\text{fence}^{(1)}\ \text{(あれば)}
   \Bigr)
   \]

2. リターン打球時刻 `t_hit` を以下の範囲から一様サンプリングする：

   \[
   t_\text{hit} \sim \mathcal{U}\bigl(
      t_{b1}^{(1)},\ t_\text{stop}^{(1)}
   \bigr)
   \]

3. 実際のタイムライン上では、
   - `t ∈ [0, t_hit]` が 1ショット目
   - `t ≥ t_hit` から 2ショット目の軌道になる。

### 5.4 2ショット目（リターン）の初期条件

リターン（2ショット目）の初期位置は、「打ち返し時点のボール位置」とする：

\[
\mathbf{p}_0^{(2)} = \mathbf{p}^{(1)}(t_\text{hit})
\]

一方、初期速度・スピンは「相手が新たに打つ」とみなして、
**改めてサンプリングし直す**：

\[
\mathbf{v}_0^{(2)}, \boldsymbol{\omega}_0^{(2)}
\]

は 4 章と同様のルールでサンプリングするが、

- 向きは now far → near（1ショット目の逆方向）
- 速度レンジ・スピンレンジは同じか、別に設定してもよい

とする。

1ショット目の速度と 2ショット目の初期速度は連続ではなく、
**打点で速度ベクトルが「リセットされる」** ことになる。

### 5.5 2ショット目のシミュレーション（相手 → 打ち出し側）

2ショット目についても、1ショット目と同様にシミュレーションし、

- 1バウンド目時刻: `t_b1^{(2)}`
- 2バウンド目時刻: `t_b2^{(2)}`
- フェンス接触時刻: `t_fence^{(2)}`

を求める。

ここでも、4.4 節の成功条件を適用する：

- 2ショット目の 1バウンド目が、**打ち出し側コートのシングルスエリア内**でない場合は
  「2ショット目がコート外」とみなし、このラリーは reject（やり直し）となる。

### 5.6 シーン終了時刻 t_end

BLCS の 1 シーンは、「t = 0 の初期打球」から
**2ショット目の 2バウンド目 or フェンス直撃** までの軌道とする。

- 2ショット目の終了候補時刻：

  \[
  t_\text{stop}^{(2)} = \min\bigl(
      t_{b2}^{(2)},\ t_\text{fence}^{(2)}
  \bigr)
  \]

- シーンの終了時刻：

  \[
  t_\text{end} = t_\text{stop}^{(2)}
  \]

- シーンの時間範囲は

  \[
  t \in [0,\, t_\text{end}]
  \]

である。

## 6. セル分割によるショット分布の制御

ラリーのショットを「どこからどこへ打ったか」という観点で多様にしたい。
ここでは

- **from_cell**: ボールが打たれた位置（プレーヤー立ち位置）
- **to_cell**: そのショットの 1バウンド目位置

をセル単位で分類し、`from_cell × to_cell` の分布をコントロールする。

### 6.1 to_cell（到達セル）: コート内 3×3 グリッド

to_cell は、従来どおり **シングルスコート内だけ**を対象にした 3×3 グリッドとする。

各サイド（near / far）ごとに：

- x 方向（左右）:
  - 範囲: `[-HALF_SINGLES_WIDTH, +HALF_SINGLES_WIDTH]`
  - 等間隔で 3 分割 → 列 index `j ∈ {0,1,2}`（左・中央・右）

- y 方向（前後）:
  - near サイド: `[-HALF_LENGTH, 0]` を 3 分割 → 行 index `i ∈ {0,1,2}`
  - far サイド: `[0, +HALF_LENGTH]` を 3 分割 → 行 index `i ∈ {0,1,2}`

各サイドの to_cell は

- `to_cell = (side, i, j)`
  - `side ∈ {near, far}`
  - `i` = ベースライン側〜ネット側
  - `j` = 左〜右

で表す（合計 9 セル / サイド）。

### 6.2 from_cell（出発セル）: フェンスまで拡張した 20 セル

from_cell は、**プレーヤーが立ちうる「フェンス内全域」**をカバーしたセル分割にする。

アイデアは：

- まず **コート内 3×3 グリッド（to_cell と同じ）** をそのまま使う。
- その縦横のグリッド線を、**フェンスまでまっすぐ延長する**。
- すると、図のように

  - 左側に 4 つのセル（コート外〜フェンス内）
  - 手前側に 3 つのセル（ベースラインより手前〜フェンス）
  - 右側に 4 つのセル（コート外〜フェンス内）

  が追加で現れる。

つまり、1 サイドあたりの from_cell は：

- **コート内 3×3**: 9 セル
- **左側の外周帯**: 4 セル
- **手前側の外周帯**: 3 セル
- **右側の外周帯**: 4 セル

→ 合計 **9 + (4 + 3 + 4) = 20 セル**

#### 6.2.1 直感的な形状

near サイドを上から見たラフな図（○ がコート内 3×3）：

```text
フェンス
┌────┬────┬────┐
│ L1 │ C1 │ R1 │
├────┼────┼────┤
│ L2 │ C2 │ R2 │
├────┼────┼────┤
│ L3 │ C3 │ R3 │   ← ここまでがコート内 3×3
├────┼────┼────┤
│ L4 │ B1 │ R4 │   ← ベースラインより手前〜フェンス
└────┴────┴────┘
          フェンス
````

* `C1..C3` が **中央 3 列 × 3 行 = 既存の 9 セル**
* `L1..L4` が **左 4 セル**

  * 上 3 セル（L1〜L3）は「コート左外（ネット〜ベースライン）」
  * 一番下（L4）は「ベースラインのさらに手前〜フェンス」
* `R1..R4` が **右 4 セル**（左側と対称）
* `B1` 列は、ベースラインより手前〜フェンスの領域を
  コート幅方向に 3 分割したセル（B1-left, B1-mid, B1-right） → 計 3 セル

> コート外のセル（L1〜L4, R1〜R4, B1系）は、
> 必ずしも等しいサイズでなくてよい。
> 「フェンス内をそれなりに分解できていれば OK」という設計。

far サイドについても、near サイドと鏡対称になるように
同じルールで 20 セルを定義する（y 軸方向の符号が反転）。

#### 6.2.2 from_cell の ID 付け

実装上は、各サイドごとに

* `from_cell_id ∈ {0, 1, ..., 19}`

の整数 ID を振り、別途

* その ID が「コート内 3×3 のどこか」
* あるいは「左外 / 右外 / 手前外のどのセル」

に対応するかをテーブルで持てばよい。

### 6.3 ショットごとの from_cell / to_cell

ショット (s) について、

* **出発セル（from_cell）**:

  * ショットの **初期位置 (\mathbf{p}_0^{(s)})** が属する
    「そのサイドの from_cell（20 セル）」のいずれか。

* **到達セル（to_cell）**:

  * ショットの **1バウンド目位置 (\mathbf{p}_{b1}^{(s)})** が属する
    「相手サイドの to_cell（コート内 3×3）」のいずれか。

1ショット目（near → far）では：

* `from_cell.side = near`（フェンス内のどこからでも）
* `to_cell.side   = far` （far コート内 3×3）

2ショット目（far → near）では：

* `from_cell.side = far`
* `to_cell.side   = near`

となる。

### 6.4 分布の制御（均等化）

**目標**:
`(from_cell, to_cell)` の組み合わせごとに、
おおよそ同数のショットがデータセットに含まれるようにする。

方法（イメージ）:

1. 全 `(from_cell, to_cell)` 組に対してターゲット本数 `N_target` を決める。
2. ショットを生成するたびに、

   * 1ショット目・2ショット目それぞれの `(from_cell, to_cell)` を計算し、
   * まだ `count[from_cell, to_cell] < N_target` なら **採用**、
   * それ以上なら **破棄**（または低確率で採用）する。
3. 1ショット目・2ショット目ともに十分なバリエーションが確保されるまで
   サンプリング＆シミュレーションを繰り返す。

> これにより、「ベースライン中央からクロス」「フェンス近くからロブ」「かなり外の位置からストレート」など、
> 出発位置の広がりも含めて多様なショット分布を作り込める。

## 7. カメラ投影とデータ形式（BLCS 用）

### 7.1 カメラ設定

カメラ位置・向きは、PLCS で定義した
「フェンス周辺＋少し内＋少し外」のサンプリングルールをそのまま用いる。

1シーンに対して複数カメラ（デフォルト8台）をランダム配置し、
**ボール視認率**（ボールが画面内かつ手前にあるフレームの割合）でフィルタリングする：

- `num_cameras_sampled`: 試行するカメラ数（例: 8台）
- `ball_visibility_threshold`: ボール視認率の閾値（例: 0.8 = 80%以上）

視認率が閾値を超えたカメラのみが保存される。

### 7.2 シーン単位の保存形式（PLCS 統一形式）

**1シーン = 1ファイル**（複数カメラを含む）の形式で保存する。
これは PLCS の Human Pose データと同じ形式に統一されている。

```text
scene_000000.npz
├── meta (JSON)
│   ├── scene_id           # "scene_000000"
│   ├── from_cell          # 出発セル ID (0-19)
│   ├── from_side          # "near" or "far"
│   ├── category           # "in_court", "out_court", "direct_net", "direct_fence"
│   ├── to_cell            # 到達セル ID (0-19, カテゴリによっては -1)
│   ├── num_frames         # フレーム数 T
│   ├── fps_out            # 出力フレームレート (30)
│   ├── sim_fps            # シミュレーションレート (240)
│   ├── t_net              # ネット接触フレーム (-1 if none)
│   ├── t_fence            # フェンス接触フレーム (-1 if none)
│   ├── t_bounce1          # 1バウンド目フレーム (-1 if none)
│   ├── t_bounce2          # 2バウンド目フレーム (-1 if none)
│   ├── num_cameras_sampled # 試行カメラ数
│   └── num_cameras        # 保存カメラ数
│
├── ball_pos_world [T, 3]  # ワールド座標（メートル）
├── ball_pos_norm [T, 3]   # 正規化座標（学習ターゲット）
├── ball_vel_world [T, 3]  # 速度
├── num_cameras            # 保存カメラ数
│
├── cam_0_params (JSON)    # カメラ0のパラメータ（内部・外部）
├── cam_0_ball_uv [T, 2]   # カメラ0でのボールUV座標
├── cam_0_ball_visible [T] # カメラ0でのボール可視性
├── cam_0_ball_visibility_ratio  # ボール視認率
├── cam_0_court_kp_uv [20, 2]    # カメラ0でのコートKP UV
├── cam_0_court_kp_visible [20]  # カメラ0でのコートKP可視性
├── cam_0_court_visibility_count # 可視コートKP数
│
├── cam_1_params (JSON)    # カメラ1のデータ
├── cam_1_ball_uv [T, 2]
├── ...
└── cam_N_...              # カメラN-1まで
```

### 7.3 学習時のデータ形式

BLCS モデルの学習時には、Dataset クラスが1シーン・1カメラを選択して返す：

- `camera_mode: "random"`: エポックごとにランダムなカメラを選択（デフォルト）
- `camera_mode: 0`: 常にカメラ0を使用

**入力**:
- `ball_uv`（`[T, 2]`）: ボールの2D軌道
- `court_kp_uv`（`[20, 2]`）: コートキーポイントの2D座標

**出力（教師ラベル）**:
- `ball_pos_norm`（`[T, 3]`）: 正規化された3D軌道

## 8. 評価指標

BLCS の評価では、以下の指標を使用する。

### 8.1 位置誤差

| 指標 | 説明 |
|------|------|
| `mean_position_error_m` | フレーム単位の L2 誤差の平均（メートル） |
| `mean_x_error_m` | X軸方向の絶対誤差平均 |
| `mean_y_error_m` | Y軸方向の絶対誤差平均 |
| `mean_z_error_m` | Z軸方向の絶対誤差平均 |
| `mean_endpoint_error_m` | 終端フレームの位置誤差平均 |

### 8.2 精度（Accuracy）

BLCS では、`position_threshold_m` / `endpoint_threshold_m` を基準に、固定の倍数で複数の精度指標を定義する。

デフォルト設定（`position_threshold_m = 0.3`, `endpoint_threshold_m = 0.5`）では、以下の指標が得られる：

| 指標 | 説明 |
|------|------|
| `position_accuracy_0_3m` | GT から 0.3m 以内のフレーム割合（`position_threshold_m` の 1倍） |
| `position_accuracy_0_6m` | GT から 0.6m 以内のフレーム割合（`position_threshold_m` の 2倍） |
| `position_accuracy_1_2m` | GT から 1.2m 以内のフレーム割合（`position_threshold_m` の 4倍） |
| `endpoint_accuracy_0_5m` | 終端位置が GT から 0.5m 以内のシーン割合（`endpoint_threshold_m` の 1倍） |
| `endpoint_accuracy_1m`   | 終端位置が GT から 1.0m 以内のシーン割合（`endpoint_threshold_m` の 2倍） |

### 8.3 設定例

```yaml
metrics:
  # Position accuracy thresholds (frame-wise)
  #  position_threshold_m の 1倍・2倍・4倍に対して
  #  position_accuracy_XXXm が自動的に計算される。
  position_threshold_m: 0.3   # 例: 0.3m, 0.6m, 1.2m

  # Endpoint accuracy thresholds (sequence-wise)
  #  endpoint_threshold_m の 1倍・2倍に対して
  #  endpoint_accuracy_XXXm が自動的に計算される。
  endpoint_threshold_m: 0.5   # 例: 0.5m, 1.0m
```

PLCS の評価指標と揃えた形式でまとめることで、
「プレーヤー位置推定（PLCS）」と「ボール位置推定（BLCS）」を並べて比較できるようにする。
