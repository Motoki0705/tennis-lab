定期的に起きて進捗を見る待ち方（`ScheduleWakeup` や /loop の tick）は、起きるたびにコンテキスト全体を読み直すため、トークンを大きく消費する。ユーザーは、完了・失敗・プロセス終了のときだけ起きる待ち方を求めている。同じ指示が3回出ており、重要度が高い。

Colabのjobも同じ。実装や起動の準備は子（Codex・サブエージェント）に任せてよいが、長時間jobの完了・異常終了・VMの消失の監視は親自身が行う。子に監視を続けさせない。

**使い方:** ジョブを始めたら、Monitor か background の until ループで、完了・失敗・worker の終了・エラー文字列だけを監視してターンを終える。進捗のポーリングはしない。子へ委任するときは、監視をタスクに含めず、起動に必要な手順と成果物までで終える。
