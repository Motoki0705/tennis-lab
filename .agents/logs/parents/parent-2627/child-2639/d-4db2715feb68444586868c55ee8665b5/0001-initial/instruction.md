2. **推敲で数値・出典・図表の内容が変わっていないこと** — 推敲前後で `\ev{ID}{値}` および数値・出典の照合結果を記録する。

## 2. 推敲の具体方針（人間の指摘を徹底反映）

人間の指摘:
> Codex の論文執筆には「ただし、これは～～の条件によるので必ずしも正しくない。」のような冗長な表現が出やすい。

以下の手順で、要旨（`main.tex`）・第1〜11章（`chapters/*.tex`）・付録（`appendix/reproducibility.tex`）の全行を精読し推敲してください。

1. **除去・集約の対象**
   - キーワード（「ただし」「必ずしも」「とは限らない」「条件による」「留意」「注意が必要」「〜とは異なる」「〜は別の評価」「〜とは別」「〜とは区別」「〜に限られる」「〜にすぎない」「〜は別途」「〜だけでは」「一概に」等）を含む冗長な但し書き。
   - キーワードを含まなくても、**各節の結果の直後に繰り返される一般的な但し書き・自明な予防線・同条件の重複記述**（例：「この支持率は〜を測る」「これは〜とは別の評価となる」「被覆は〜であり正解率は別途評価を要する」「この介入は〜であり〜はこの採点対象から外れる」「この単体測定は〜を比較する」「〜は個別に評価する必要がある」「〜はこの設計からは推定できない」など、すでに設定節・表キャプション・第10章に書いてある内容の反復）。
2. **整理の原則**
   - **実験条件は実験設定の節または表の注に一度だけ書く**。本文中で同じ母数・条件・対象外の説明を何度も繰り返さない。
   - **結果の解釈に本当に必要な限界・未評価事項は第10章（限界と今後の課題）に集約する**（すでに第10章にある重複事項は前章から削るだけでよく、第10章にない重要事項のみ第10章へ移す）。
   - 論文全体として、主張と根拠が端的に伝わる自然な日本語の技術報告（DINOv3 技術報告のような簡潔で明快な文体）に整える。
   - **ただし、事実を歪める誇張は禁止**。未マージ計測・単一seed・独立3D参照未計測・T=1とMDDの差といった不可欠な境界条件は、第10章または該当表の注・条件記述に**簡潔に一度だけ**正確に残す。
3. **不変条件（厳守）**
   - **数値・単位・母数・出典・図表の数値内容・`references.bib`・`tables/*.tex`・`figures/**` は変更しないこと。**
   - 本文の推敲では、`\ev{ID}{値}` の ID と値を保持する（重複する条件記述を本文から表注や第10章へ集約したことで、同じ `\ev{ID}{値}` の反復回数が減ることは許容するが、**すべての数値事実と根拠 ID の集合は一切失わない**こと）。
   - 推敲前（`HEAD` / `c16959632`）と推敲後で、以下を自動スクリプトまたは照合手順で比較し `paper/tennis_scene_architecture/evidence/polish.md` に記録する：
     - 冗長留保パターン別の出現件数（推敲前 vs 推敲後）
     - 全変更箇所の一覧（ファイル名・箇所・変更前の文・変更後の文・処理区分［削除／簡約／第10章または表注へ集約］）
     - 数値・`\ev` 根拠ID・`tables/*.tex`・`figures/**`・`references.bib` の不変照合結果（`check_evidence.py`, `make_tables.py --check`, `prepare_figures.py` の通過を含む）。

## 3. 最終 PDF のビルドと全ページ視覚確認

1. すべての新規・更新ファイルを `git add -f` で登録した後、空の `build/` から `bash paper/tennis_scene_architecture/build.sh --check-tracked` を実行し、終了コード 0（警告・Overfull・文字欠落・未解決参照/引用・未追跡入力 0 件）を確認する。
2. `pdftoppm -png -r 150 paper/tennis_scene_architecture/build/main.pdf [local path]` 等で **全ページ（1ページ目〜最終ページまで1枚も飛ばさず）** をレンダリングし、すべてのページ画像を実際に目視確認する。
   - 確認観点: タイトル・要旨の配置、図表の枠・文字の鮮明さ、ページ跨ぎの不自然な大余白やフロート偏り、表の列幅・罫線・桁揃え、数式・記号の描画、参考文献・URL折返し、日本語組版。
   - もし明らかなレイアウト崩れや不自然な大余白（例：`\FloatBarrier` による半頁以上の空白や図表の偏り等）が見つかった場合は、レイアウト調整（図幅や `[tbp]` 配置調整等）を行って再ビルド・再全頁確認すること。
   - `[local path]` 等の作業画像は確認後に削除し、リポジトリへ残さないこと。
3. `paper/tennis_scene_architecture/evidence/build.md` を更新し、以下をすべて記録する：
   - ビルド環境（TeX Live / LuaHBTeX / LuaTeX-ja / latexmk / Poppler のバージョン）
   - 実行コマンドと終了コード・警告 0 件の根拠
   - 最終 PDF のページ数・バイト数・SHA-256（コミット済み HEAD の直前ビルド、およびコミット後に再確認して一致した記録）
   - **全ページ（p.1 〜 最終頁）のページ別目視確認チェック表**（各ページの主内容・図表・確認結果）。

## 4. スコープ・提出手順（高速並列レビュー対応）

- 変更対象は **`paper/tennis_scene_architecture/` 配下のみ** に限定する（`knowledge/`・`src/` は触らない、`build/` 生成物・PDF は絶対にコミットしない）。
- 新規・変更ファイルは共有 `.git/info/exclude` の `[local path]` を踏まえて個別パスで `git add -f` する。
- コミット済み HEAD で以下すべてを通過させる：
  - `.venv/bin/python -B paper/tennis_scene_architecture/scripts/make_tables.py --check`
  - `.venv/bin/python -B paper/tennis_scene_architecture/scripts/prepare_figures.py`
  - `.venv/bin/python -B paper/tennis_scene_architecture/scripts/check_evidence.py`
  - `bash paper/tennis_scene_architecture/build.sh --check-tracked`
  - 変更した Python スクリプトがあれば `ruff` / `mypy`
- ブランチを push し、日本語で Ready PR（`Closes #2639`、`## 変更内容`、`## 受入と検証`、`## 実行証拠` の JSON に現 HEAD の `head_sha`・ページ数・`pdf_sha256`・推敲前後件数・全頁確認数を明記）を作成する。
- **PR CI 完了は待たず**、Ready PR 作成直後に最終サマリーを報告して `PARENT_RESULT {"schema_version":1,"state":"done","wait":null}` で終了する。
