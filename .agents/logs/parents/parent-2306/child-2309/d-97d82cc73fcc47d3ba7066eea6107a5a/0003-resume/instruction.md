## 指摘（原文）

### 1. 共有 hook 設定が既存の Issue 補足を agy 起動前に止める
実行検証と静的推論。固定 checkout の `.agents/hooks.json` に対し、既存ランナーと同じ排他作成を実行して `FileExistsError` を確認しました。`issue_supplement/workspace.py:141` は確定コミットを使い捨て worktree に展開するため、この追跡ファイルが毎回入ります。`lib/agy_hook.py:53` が同じパスへ監査用 `PreToolUse` を排他作成し、`lib/agy_headless.py:394` で `invalid_input` になるため、GitHub Actions の初回・再試行とも固定版 agy の起動前に失敗します。citation、explain_html、AGY smoke のテンプレート・権限プローブは独立した一時 workspace を使うため、この衝突の対象外です。既存の hook 拒否・監査・完全性検査を保ったまま手動親用設定を分離し、既存の補足 E2E を拡張して、手動親用設定を含むコミットからもコマンド拒否と補足成功を両方検証してください。

### 2. `.venv` のない checkout で共通 hook が起動できず、未読提示が成立しない
実行検証と静的推論。`.venv` のない固定 checkout の `.agents` から `.agents/hooks.json:6` のコマンドを実行すると、インタープリターが見つからず終了値 127 になりました。対話・print・ACP の判定は Python 起動後にあるため、同じ設定をロードする非対象起動もその判定に到達できず、`.venv` がある場合は判定のために毎回 Python を起動します。掲示板側の `delivery.py:252` は hook が利用できない場合も `awaiting_hook` を返します。`test_agy_parent.py:258` は Python ファイルを直接呼ぶため、設定の相対パスやインタープリター欠落を検出できません。実際の hook 設定を通る代表テストで、非対象起動の分離と、手動親で必要な実行環境が欠けた場合の明示診断を確認してください。

### 3. agy の照合失敗を正常な未読なしや外部参照として返す
実行検証と静的推論。`agy_hook.py:44` は `caller_tui()` の `ValueError` をすべて対象外扱いします。対応する会話 ID を環境と入力に渡し、agy 祖先のない状態で実際の Python エントリーポイントを実行すると、診断なしで `{}` と終了値 0 が返りました。`caller_tui()` は `[local path]` の取得失敗も同じ例外へ変換するため、手動親の照合異常を print・ACP・ネストと区別できません。また `parent/cli_impl.py:877` の `status` は、agy の識別子がある場合もロックや trajectory の不一致を握りつぶし、通常の外部参照を返します。想定内の対象外・旧会話イベントは提示せず、手動親の照合異常は明示エラーにしてください。既存の拒否テストに、異常時の hook と `status` の戻り値を加えてください。

### 4. 通常の Herdr 同期で呼出元 TUI と対象 pane の PID を照合していない
静的推論。`herdr_labels/service.py:233` の通常 `sync()` は呼出元の agy を検証した後、その PID と開始時刻を使わず、Herdr が返した pane を別途検査します。`Guard._check_process()` が要求するのは対象 pane のプロセスが同じ会話 ID のロックを保持することまでです。ロックは HOME ごとに独立しているため、別 HOME の TUI が同じ会話 ID を保持していると、誤った pane を指す Herdr 環境で別 TUI に担当表示を適用できます。`agy_session_changed()` には PID と開始時刻の一致検査があります。`register` 後の表示同期を含む通常経路でも同じ照合を行い、対象 pane の不一致時に表示や表示先の記録を変更しないことを既存の fake Herdr で検証してください。

### 5. 共有掲示板を v6 へ切り替える運用手順が欠けている
実行検証と静的推論。メモリ上の v5 DB に親・人間宛ての配送と既読を作り、移行後に既存行・外部キーを保持することを確認しました。同じ v6 DB を base の版検査に渡すと `unknown board schema version` で拒否されました。新コードの読み取りと Web は逆に v5 を拒否し、Web は移行を実行しません。PR 本文は移行とラベル同期を残作業に挙げていますが、`board/README.md:637` には共有 DB と既存 worktree・常駐 Web の切替順がありません。マージ前に、新コードで移行を起動する担当操作、共有 DB の版と Web の確認、旧コードを使う worktree の切替順を明記してください。`agent:agy` の同期は既存の `ops/issues/README.md:55` の管理者手順へリンクできます。
