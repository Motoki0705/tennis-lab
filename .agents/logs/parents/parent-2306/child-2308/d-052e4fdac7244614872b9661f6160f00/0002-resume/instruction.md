調査報告を人間と検討し、次の推奨案がすべて承認された。この内容で実装へ進む（#2308 本文も更新済み）。

1. 宣言形式は案1: 自由文の最終メッセージ末尾に必須のJSON1行 `PARENT_RESULT {...}`。待たないターンも `done` / `needs_parent` と `wait: null` を必須にし、欠落・重複・位置違い・JSON不正・未知の種類や版・不足・型違いをCLIで明示エラーにする。
2. 1回の宣言で複数のqueue jobを待てる。すべてが終端したら1回だけ再開し、全jobの結果をまとめて渡す。
3. CLIによる監視と自動再開は手動委任（`run-worker`）の経路だけに実装する。自律親（start-worker / continue-worker / dispatcher）には共通テンプレートの「宣言して終了」だけが届き、自動再開は別Issueとする（実装しない。文書に境界を書く）。
4. Colabの学習安定確認は今回の監視対象外。現行の parent-session の手順のまま。
5. 共通テンプレートの契約文は報告5の文案を基にする。特に「Issue本文や親の指示にある『成功まで確認』は担当全体の完了条件として扱い、CLIから結果を受け取ったターンで確かめる」を必ず含める。親向けの具体指示の良い例・悪い例を workers.md に置く。
6. 既存の自動CI・gate修正の repair JSON 契約は維持し、同じPRの監視を重複起動させない。自動再開の上限は担当単位で3回。CI成功かつ後続作業の宣言なしなら再開せず、`wait-worker` が一連の終了を返す。監視は共通ランナーの子孫回収と会話の外で所有し、同じイベントで二重に再開しない。
