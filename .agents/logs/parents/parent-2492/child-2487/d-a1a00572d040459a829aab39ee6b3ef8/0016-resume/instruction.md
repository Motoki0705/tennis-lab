# #2487 edgecrafter: TensorRT の調査を打ち切り、ログを保持する（親の判断）

前回の報告（`da55bf2a9`、ECDet 4重みの `trt16-fp32attn`、ECPose は書き換え適用不可）を受け取った。記録を承認する。

## 判断
- FP32 attention で ECDet の Recall@0.50 は 63〜70% から 78〜83% に上がったが、PT16（約98%）との差は14.56〜52.51ポイント残り、X O365 は下がった。原因は未特定。TensorRT の調査はここで打ち切る。
- 比較表には、元の TRT16 と `trt16-fp32attn` を「変換の不具合、原因未特定」として残す。精度は Pareto の判定から外す（統合担当が扱う）。PT16 が EdgeCrafter の有効な比較条件。
- 原因の特定（最初にずれる演算、batch の並び順への依存）は、EdgeCrafter が採用候補になったときの課題として、記録の「残課題」に1段落で書く。

## queue のログを保持先へコピーする
`.training_queue/logs/` のログは、完了から7日で自動削除される（`repro/` は対象外）。PR #2500 の正式レビューで、ログが消えると再採点や可視化の読込が失敗することが指摘された。#2487 の記録にも `.training_queue/logs/` を直接参照しているものがある。
- あなたの branch の記録が `.training_queue/logs/` を参照していれば、そのログを自分の保持先（自分の出力ディレクトリ）に SHA-256 付きでコピーする。記録の参照と、それを読むコードを、コピー先に揃える。元の SHA-256 と一致することを確かめる。
- 親が #2492 関連のログ101件を `.worktree-outputs/parent-2492-queue-log-archive/logs/` に複製済み（`SHA256SUMS` 付き）。元ログがすでに消えていたら、そこから取ってよい。
- ログが消えた状態を模擬して、読込が保持先から動くことを確かめるテストを足す（読むコードがある場合）。
- これから入れる job のログも、完了後に同じようにコピーする。

## 終わり方
テストと pre-commit を通して push する。最終回答には、コピーしたログの件数と保持先、直した記録、push した HEAD を書き、`PARENT_RESULT {"schema_version":1,"state":"done","wait":null}` を返す。
