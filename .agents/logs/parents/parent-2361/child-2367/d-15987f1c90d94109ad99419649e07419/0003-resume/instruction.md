# PR #2372 正式レビュー（major）への対応

正式レビューの指摘4件を、親はすべて採用した。各指摘の全文と根拠リンクは、このPRのレビュー記録にある。修正ごとに、修正前に失敗して修正後に通る回帰テストを付ける。
直したら、検証してcommit・pushし、PR番号と完全なHEADを宣言して終了する。CIの結果は後続のターンで受け取る。
`tests/e2e/agents_ops/test_manual_worker_runs.py` の扱いは変えない。#2371 のマージ後に、別のターンで載せ直しと取り下げを指示する。

## 1. 共通ランナーの容量拒否で、委任が終了扱いになる
dispatcherの事前検査を通った後に `agent_exec.sh` 側で容量不足・測定エラーになると、CLIが起動していないのに `capacity_blocked` が失敗結果として保存される。その結果、dispatcherは予約を `ended` にし、手動委任は `runtime_failed` になる。初回起動ではsession IDもないので、`--resume` でも続けられない。
- 実行済みのターンと区別できる「起動しなかった拒否」（例: `agent_spawned=false`）を結果に残す。dispatcherと手動委任（`parent/worker_followup.py` など）は、それを終了とみなさず、同じ委任・予約を再試行できる状態に保つ。
- ランナーの起動後に拒否を受け取る経路を、dispatcherと手動委任の両方でテストする。

## 2. 容量不足で、正式レビューの起動枠が消費される
`review/parent_review_impl.py` は、ランナーを起動する前に `agent_invocations=1` を保存する。そのため、終了75が `review_failed` になり、容量が戻った後も再開できない。
- レビュー担当のCLIが起動しなかったことを保存結果から確かめ、同じレビュー回を再試行できる分岐を作る。回帰テストも付ける。

## 3. 送信前の失敗で、Windows通知が失われる
状態を保存してから送信しているため、PowerShellが起動できないと、次の測定でも送信を試みない。また、`[local path]` はUbuntuを再起動すると消えるので、不足が続いていれば通知が重複し、再起動中に回復すれば回復の通知が出ない。
- CI用の一時的な判定（`[local path]`）と、通知の履歴を分ける。履歴は再起動しても消えない場所に置く（user state dirなど）。
- 確実に送れなかった場合（PowerShellの起動失敗など）は、次の測定で送り直す。送れたかどうか分からない場合は、重複を避ける側に倒す。どちらに分類したかはjournalに残す。

## 4. 時計が巻き戻ると、期限切れのCI判定が再び有効になる
- 判定の鮮度は、時刻補正の影響を受けない時計で決める。プロセスをまたいで比べられる時計（例: `CLOCK_BOOTTIME` と、`[local path]` を組にする）を使い、boot_idが違えば拒否する。
- 90秒を過ぎた判定が、壁時計の巻き戻しや再起動で復活しないことを検証する。
