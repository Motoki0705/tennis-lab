親の判断（#2051 コメント 6887035560 の「WSL再起動後の device 相違」への回答）:

再起動で st_dev が変わるのは、この WSL では E: の ext4 ディスク追加などでブロックデバイスの並びが変わるためで、6件に限らず、追跡中の全worktreeの個体照合が再起動のたびに壊れる一般的な不具合とみなす。PR #2052 の中で次のとおり直してほしい。

1. 個体照合のキーから st_dev を外し、再起動をまたいで安定するファイルシステム識別子に置き換える。候補は `statfs` の f_fsid（ext4 ではUUID由来）や mountinfo から引くファイルシステムUUID。どれを使うかと、WSL・ext4・drvfs（[local path] など）での安定性の根拠をPR本文に書く。識別子を取れない場合は、黙って st_dev へ戻らず失敗として記録する（静かなフォールバック禁止）。世代の照合は inode に加えて birth time（statx btime）で行い、inode 再利用を別個体と判定できるようにする。
2. 既存の state・intent・証拠（device を含む旧形式）の移行: 旧レコードは、inode・birth time・パス・Git管理ディレクトリの登録（.git/worktrees/<id> と gitdir の対応）がすべて一致する場合だけ同じ個体として新形式へ移す。一致しない旧intentは、永続的な失敗として残さず、対象の消失・別個体として閉じ、理由を記録する（その場合、同じパスの新しい個体は新規として通常の期限判定を受ける。birth time 由来の作成時刻なので期限は変わらない）。移行は一度で冪等にし、中断から再実行できるようにする。
3. テスト: device だけが変わった（inode・btime・登録が一致）場合に同一個体として扱われ、6件相当が1件ずつに収まること。inode が同じでも btime が違う場合や登録が違う場合は別個体になること。識別子が取れない場合に失敗すること。修正を外すと失敗すること。
4. 実ホスト: 読み取りだけで、6件と追跡中の他のworktreeについて、移行後の照合が一致する見込みを示す（本番stateのコピーでの公開dry-runで、同じパスが1件ずつになり preflight・エラーの件数が期待どおりであること）。本番の削除・unit操作・state更新・signal はしない。
