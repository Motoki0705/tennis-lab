# PR #2227 正式レビューのmajor 5件への対応

正式レビュー（parent-1734-c4ce21fb9f064e0d87ce20be2704431e）で、major指摘が5件出ました。親は5件とも直すと判断しました。再レビューは行いません。修正してCIが通ったら、親がmergeします。指摘の全文は `parent merge-status --run-id parent-1734-c4ce21fb9f064e0d87ce20be2704431e` で読めます。

1. **既存exportの採用**: `overwrite=true` で同じcomponentを再利用すると、既存の `scene.npz` を検証しないまま、チェックサムを採用し直してしまう。採用する前に既存のexportを検証すること。強制公開から、次回の通常の再開まで、破損のテストを通すこと。
2. **同じ世代の同時公開**: 単一の入口と一括の入口が、同じ世代のディレクトリを競って作ると、後から来た側がclip lockの外で `OSError` になる。その結果、`continue_on_error` でも、残りのclipがblockedになる。同期点を設けたテストで再現し、直すこと。
3. **共有成果物の最終の再検証**: 一括の入口でも、公開の直前に、共有のcourtとcourt_sideを再検証すること。単一の入口と同じ共通の最終化処理を使い、同じ確認を2か所に作らない。最後に使ったあと、公開の前に変更を注入するテストを書くこと。
4. **重みのスナップショット**: `publication_identity()` と計画の作成とで、同じ資産のスナップショットを使うこと。重みを差し替えるテストを、この境界まで広げること。
5. **X3Dの推論の記録**: `X3DDPTPredictor.predict` の実際の推論の入口で、recorderのイベントを出すこと。通常のbatchと末尾のbatchの記録を、CPUのテストで確かめること。#1757のbenchmarkは、ball推論を含めて計測するので、これが必要になる。
