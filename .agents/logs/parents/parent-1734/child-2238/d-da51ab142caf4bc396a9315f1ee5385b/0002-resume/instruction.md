# PR #2240 正式レビューのmajor指摘への対応（親 #1734 から #2238 へ）

正式レビュー（gpt-6.2-sol / xhigh）で、次の2件のmajor指摘が出た。2件とも妥当と判断する。直してください。

## 1. 既定FP32で既存キャッシュを再利用できなくなる

静的な推論とハッシュの実行検証です。`definition.py:187` の人物検出・追跡・姿勢推定では、既定でも `precision` と `device` が設定identityに加わり、追跡から旧 `pose_precision: float32` が消えます。実装ハッシュを固定しても3段のキーが変わります。通常入口で使う `src` 全体の実装ハッシュも両コミットから再計算して差を確認しました。`execution_plan.py:192` の判定では、旧FP32成果物はexecute時に再計算され、load専用時にはidentity不一致で停止します。追加テストは新実装内の設定差を検出します。基準mainで保存した成果物を既定FP32と明示FP32で再利用でき、BF16・FP16は別のキーになることを回帰テストで確認してください。

## 2. 姿勢なし追跡による人物ID差を計測で切り分けられていない

静的な推論と保存結果の照合です。`pose_scope.py:123` は再生側の `device` をCPUに変更し、標準設定で有効なカメラ間対応のCLIPもCPUで再推論します。比較先はCUDAで保存した人物対応です。clip_000の人物ID差2件には追跡profileとCLIP実行deviceの両方の変更が含まれ、knowledge 000050の「姿勢なし追跡により人物対応が変わった」という因果の説明には対照が足りません。両profileの人物対応を同じdeviceで計測するか、人物ID差を複合条件の観測として明記し、姿勢の有無に帰属できる結論を固定済み特徴で比較した追跡・選別までに限定してください。

## 親の方針
- 1（既定fp32のcache互換）: 既定のfp32では、基準mainで保存した成果物のcache identityが変わらないようにする。明示的なfp32も同じキーにする。bf16・fp16は別のキーにする。指摘のとおり、基準mainの成果物で回帰テストを書く。互換を保てない理由があれば、その理由と影響範囲をPRに明記して止め、報告する。
- 2（姿勢なし追跡の因果）: 追加のGPU計測はしない。knowledge 000050とPRの記述を直す。人物IDの差は、追跡profileとCLIPの実行deviceの両方を変えた複合条件の観測であると明記する。姿勢の有無に帰属できる結論は、固定済みの特徴で比較した追跡・選別までに限定する。
- 人間の決定（2026-11-18）: meiji_4camの本番では、ViTPoseとDINOの両方をfp16で実行する（既定はfp32のまま）。このPRでは既定を変えない。
- CPUの関連テスト、pre-commit、CIを通し、PR本文に各指摘への対応を追記する。merge・closeは親が行う。
