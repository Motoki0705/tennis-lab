# PR #2271 正式レビューのmajor指摘への対応

正式レビュー（parent-1734-0a8a81d709fd447993fe62020461a2cc）で、major指摘が1件出ました。直してください。再レビューは行いません。修正してCIが通ったら、親がmergeします。

## 指摘
画像のSHA-256照合は、実行するときにしか行われない。
- `ExecutionPlan` のcache keyには、実際にデコードに使った条件が入っていない。具体的には、`VideoCapture` が選んだbackendと、その設定。
- 特徴nodeのkeyに加えた前処理の条件（OpenCVの最適化の設定など）が、`publication_identity()` に入っていない。

そのため、デコードの条件が変わったときに困ることが起きる。
- 新しく実行すると、`image_mismatch` を記録して再推論する。
- 一方、cacheから再開すると、前回の人物IDと照合の診断をそのまま採用してしまう。
- データセットの完成マーカーも、計画を実行する前に採用されてしまう。

## 直し方
- 実際に効いているデコードと前処理の条件を、nodeのidentityと完成マーカー（publication identity）の両方に入れる。
- 同じ条件の取り出し方を2か所に作らない。1つの関数から両方に渡すこと。
- 条件が変わったときに古い成果物を採用しないことを、CPUの統合テストで確かめる。
- 既存の3clipの保存成果物を、黙って無効にする変更になるなら、そのことをPR本文に明記する。#1757のbenchmarkが、この再利用を別の条件として測る。

最後に、HEAD・テスト・CIの結果を報告してください。背景にプロセスを残さないでください。
