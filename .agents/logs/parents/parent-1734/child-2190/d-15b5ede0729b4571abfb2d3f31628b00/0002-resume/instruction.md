# #2190 planningへの回答（実装を承認する）

## 人間の判断（2026-11-16）
- 参照の草案: 4cameraとも「そのまま使う」と人間が承認した。`references.json` の `human_reviewed` / `approved_for_evaluation` を、承認日と根拠つきで true にしてから評価に使う。参照の点は変えない。
- 正しさの許容差: 1920×1080の元画像で、画像内に投影される参照のコートkeypointと推定の差が **平均10px以下かつ最大25px以下** なら「正しい推定」とする。
- 目標:
  - meiji_4camで、誤った推定の採用を0件にする。
  - 正しい推定の採用率を90%以上にする（cameraごとにも報告する）。
  - meiji_4cam以外（meiji_3cam・tennis_clip・court_detectionのval/test）で悪化させない。

## 親の判断
- 実装方針は、planningの案を承認する。
  - 採否の基準: 可視線の一致、独立した支持点・線の分布、ホモグラフィの悪条件性、外挿の安定性。
  - 後処理の見直し: 境界・重複点の扱い、候補の順位、線ごとの診断。
- 評価は3条件（旧処理／採否だけ変更／後処理も変更）で行う。
- 許容差・目標は、結果を見てから変えない。未達ならそのまま報告する。
- 参照はmeiji_4camの評価の正解として使う。採用条件のパラメータを、この参照に過剰に合わせ込まない。meiji_4cam以外での回帰確認の結果を必ず併記する。
- Court評価資産の復元・split来歴の確認は、`storage_tier hydrate` などで正規に取得する。取得できなければ、その事実と代わりに使ったものを報告する。
- 品質指標（採否の根拠となるscore）は、#2191（動画内共有モード）がcameraごとの推定の選択に使う。診断として安定した名前・意味で出力する。
- GPUは共有training queue経由で使う。完了したら、PR（`Closes #2190`、日本語）・CI・knowledgeを揃えてready for reviewにする。merge・issue closeはしない。
