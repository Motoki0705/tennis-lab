## 親の指示: 参照を塗装の白線で合わせ直し、3条件の評価をやり直す

PR #2200の報告を受けました。親は clip_000 の cam1・cam2 を元解像度で拡大して確認しました。その結果、承認済みの参照（手指定の点から求めたH）は、塗装の白線から数px〜数十pxずれていました。手前のベースラインでは、推定は白線の中央に乗り、参照は白線の内側の縁に寄っています。ネット側では、参照と推定が数十pxずれています。
人間は縮小画像で承認したため、このずれは見えていませんでした。誤採用144〜176件のうち多くは、参照の誤差による判定と考えられます。人間は2026-11-16に「白線で合わせ直す」を選びました（evidence: #2150 の親note）。

### やること
1. **参照を作り直す。** cameraごとに、元解像度1920×1080の原画像の塗装の白線（各線の中心）に合わせてHを最適化します。
   - モデルのKP/LINE出力は使いません。評価対象から独立させるためです。
   - cameraは固定なので、複数のclip・frame（例: 冒頭・中盤・終盤から十数frame）の白線の証拠を合わせて使います。人物で隠れた部分は外れ値として扱います。
   - 初期値は現在の参照です。座標の規約は `src/utils/schema/court.py` に従います。
   - 線ごとの残差（白線の中心からの距離の分布）を出力します。cameraがframeによって動いていないかも、線の残差で確認します。
2. **確認用の画像を作る。** cameraごとに、元解像度の拡大crop（手前のベースライン・ネット側・左右のサイドライン）で、旧参照（青）・新参照（別の色）・白線を比べられる画像を作ります。人間に再承認してもらうための資料です。
3. **新参照を仮固定して3条件を再評価する。** `approved_for_evaluation` は、人間の再承認までは「仮」と明記します。凍結済みのraw（旧処理／採否のみ変更／後処理も変更）を、同じ許容差（平均10px・最大25px）で再評価します。GPUは不要です。
   - camera別の混同行列、正解候補がある画像の救済率、誤差、clip間のばらつきを、旧参照の結果と並べて示します。
   - 回帰の結果（Court val・synthetic test）は参照に依存しないので、再掲だけでかまいません。
4. 結果をknowledge（新しいrun node、または000070の更新）に記録し、PR #2200のbranchへcommit・pushします。
   - 参照のずれが原因だったのか、推定の誤りなのかを分けて書きます。
   - 新参照でも誤採用が残る場合は、それが推定の誤りだと画像で示してください。

### 制約
- 許容差・目標（誤採用0・正しい推定の採用90%以上）は変えません。閾値や実装を新参照に合わせて調整するのは、この段階ではまだ行いません。結果を見て親が判断します。
- 白線への合わせ方（edgeの抽出・ロバスト損失など）は、静かなフォールバックなしで一意に定めてください。合わせられないcameraや線があれば、失敗として報告してください。
- merge・issue closeは行いません。
