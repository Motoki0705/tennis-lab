# PR #2272 正式レビューのmajor 4件への対応

正式レビュー（parent-1734-1d5bbaac8d4d48019461ec1398d3786a）で、major指摘が4件出ました。親は4件とも直すと判断しました。再レビューは行いません。修正してCIが通ったら、親がmergeします。指摘の全文は `parent merge-status --run-id parent-1734-1d5bbaac8d4d48019461ec1398d3786a` で読めます。

1. **ViTPoseのUDP補正が、ほかの人物を読む**:
   - 問題: 最大値が非正の関節は `(-1,-1)` になるが、それもUDP補正の対象になる。その結果、平坦化した配列の上で、直前の人物の関節や、batchの末尾を読んでしまう。
   - 直し方: 無効な関節を補正の対象から外す。
   - テスト: 実際のデコーダーを使い、B=1と、別のclipが混ざったbatchとで、人物ごとの座標と信頼度が一致することを確かめる。
2. **Courtの出力の異常が、batch全体を止める**:
   - 問題: `validate_logits` がbatch全体で例外を出すと、`drain_batch_jobs` を抜けて、正常なclipまでblockedになる。
   - 直し方: 行に帰属できる出力の異常は、該当するclipだけに返す。
   - テスト: 障害を注入し、同じforwardの正常な行は完了・公開できることを確かめる。逐次の経路と同じ分離にすること。
3. **X3Dの予約に、FP32の入力が入っていない**:
   - 問題: X3Dの予約が、FP32の5チャネルのRGB+MDD入力を数えていない。
   - 直し方: 実際の前処理が同時に保持する量を、forwardの前に予約する。
   - テスト: 本番の解像度（720×1280、T32）で上限を超えるときは、モデルを呼ばずに明示的に停止することを確かめる。予約が増えて既定の上限で動かなくなるなら、上限の既定値を見直し、その根拠をPRに書く。黙って上限を緩めない。
4. **メモリキャッシュのヒットで、checksumを飛ばす**:
   - 問題: `batching.store_cache_bytes>0` のとき、キャッシュがヒットすると、配列のchecksumを確かめずに、既存のmmapを返す。
   - 直し方: キャッシュに入れたあとで配列が破損したら、下流に渡す前に拒否する。あるいは、検証を保証できないなら、キャッシュを無効にすることを明示的に強制する。どちらを選んだか、理由をPRに書く。
   - テスト: 既存の共有キャッシュのテストに、破損の注入を加える。
