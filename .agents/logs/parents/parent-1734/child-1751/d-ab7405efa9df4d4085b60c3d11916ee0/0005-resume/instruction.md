# 再開指示（親 #1734 から #1751 へ）: a5のBall差分の扱い

親の判断: **a5を、C3の受入として合格とする。**

根拠:
- 全mask・ID・人物系の出力は完全に一致している。
- 差はBF16のBall検出だけにある。差の大きさは、検出で最大0.129px、最終3D位置でL2最大0.362mm。ボール検出の誤差（数px）と比べて2桁小さく、下流の判断を変えない大きさである。
- 事前条件 `atol=1e-6 / rtol=1e-5` は、FP32の決定的な経路を前提にしていた。BF16の推論は、batchの組み方やkernelの選択で丸めが変わりうる。そのため、Ballについてはこの条件が厳しすぎた。

やること:
1. 受入条件を明示的に改める。Ball（BF16）は「検出のuvで0.5px以内、最終3D位置で1mm以内、observed/maskは完全一致」とする。それ以外は今の条件のままにする。改めた条件と理由（上の根拠と、親の判断であること）を、knowledge 000052とPR本文に書く。条件を静かに緩めたように見えないよう、元の条件で不合格だったことも残す。
2. 差の原因が分かる範囲で一言添える（例: compile・batchの構成の違い）。追加のGPU実行はしない。
3. CIが成功したら、PR #2182をReady for reviewにして終了する。merge・closeは親が行う。
