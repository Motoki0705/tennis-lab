# #1757: 監視をnvidia-smiを使わない方式に替える（GPUは使わない）

切り分けの結果を親が受け取りました。条件A（nvidia-smiの照会なし）は235/235frameを完走し、条件B（1秒ごとの照会）は53frame目で停止しました。親は、計測中にnvidia-smiで照会することをやめると決めました。

## 直すこと
- #1757のbenchmarkの監視（health_guard）から、計測中のnvidia-smiの照会を外す。
  - GPUメモリは、計測するプロセスの中で `torch.cuda.memory_allocated` / `max_memory_reserved` などを使って記録する。
  - 停止の検知は、heartbeatと外部の時間制限で行う。
- 実行前の環境の記録（GPU名・driver・VRAMの空き）は、計測を始める前に1回だけ、nvidia-smiかNVMLで取ってよい。その場合も、計測中は照会しない。
- peak VRAMの定義が変わる（NVMLのデバイス全体 → プロセス内のallocator）。計測項目の定義、許容誤差の文書、PR本文を、それに合わせて更新する。
- 条件1〜3と#1756の条件で、同じ監視を使う。
- 監視が黙って別の方式に切り替わる経路を作らない。

## 今回はやらないこと
- **GPUで計測しない。queueにjobを入れない。** 再投入は、人間の許可を得てから親が指示する。
- CPUのテストで、監視の動きを確かめる（heartbeatが止まったときの停止、nvidia-smiを呼ばないこと）。
