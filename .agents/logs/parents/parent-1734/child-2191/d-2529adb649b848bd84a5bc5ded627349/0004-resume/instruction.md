## 親の指示: 人間の判断を反映し、共通Hを下流で使える形に仕上げる（#2191）

### 人間の判断（2026-11-17）
人間は、確認ページで4cameraの共通H（3clip×4camera＋原寸の拡大crop）を目視しました。その結果、「緑の線は完全にコートを示している。これを下流で用いていけばよい」と判断しました。これを、共通Hの目視確認（受入の人間確認）として記録します。
あわせて、cameraの動きの自動検査は、判定できないことを理由にclipを止めないことになりました。

### やること
1. **driftの扱いの変更（明示的に）**
   - `drift_unobservable` と、線の矛盾（`non_similarity_or_conflicting_line`）は、失敗ではなく **warning（診断）** にします。共通Hをそのclipに使い、receipt・clip表・galleryに理由とframeを明示します。
   - 数値として信頼できる変位が `D_mean > 10px` または `D_max > 25px` の場合だけ、失敗のままにします（run 78では0件）。
   - 方針は設定（例: `unobservable_policy: warn|fail`）として明示し、cache identityに含めます。既定値は、人間の判断に合わせて `warn` とします。暗黙の切替や、別の経路への静かなフォールバックはありません。
   - 共通Hの成果物・推定方式・数値は変えません（bundle hashを維持します）。
2. **再評価**: run 78の診断結果を新しい方針で集計し直します。全69clip×4cameraで、使用可・warning・失敗の件数を出し、4cameraがそろって使用できるclip数を報告してください。再計算が不要なら、保存済みの診断をそのまま使ってください。
3. **knowledge**: 新しいrun（または78への追記。二重管理を避ける方を選ぶ）に、人間の目視確認と方針変更の理由を記録します。理由は、共通Hが参照と一致したこと、人間が目視で確認したこと、検査が通らない主な原因は隣接線の誤った拾い方であること（10px級の動きの証拠はない）、の3つです。限界として、「clipの途中でcameraが動いた場合、自動では検出されないことがある」と明記します。drift検査の改善（線の候補を保持し、共有した線配置で対応を検証する）は、将来の改善として残します。
4. **PRの仕上げ**: PR #2222をReady for reviewにし、本文を最新に更新します。`Closes #2191（親 #1734）` を含めます。CIの成功まで確認してください。一括CLIとの接続は #1752 の担当で、ここではしません。
