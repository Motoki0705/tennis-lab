issue #1914 の本文に、親の調査結果と対策案A〜Dがある。このターンでは実装・push・PR作成をしない。次を調べて報告する。報告は、親が人間に方針を選んでもらう材料になる。

1. **原因の確認。** CI run 43034986105（3回の試行）と、#1857 に挙がっている過去のrunのログを読み、apt準備の失敗の形を分類する。
   - 配布元に接続できない（update が時間切れ）
   - download中に install が時間切れ
   - その他
   各形の発生日時と件数を示す。GitHub runner imageに ffmpeg・rclone が入っていないことの根拠（imageの記述、ログ）も示す。
2. **システム依存テストの棚卸し。** ffmpeg・ffprobe・rclone の実行ファイルを実際に呼ぶテストを、静的な検索だけでなく実測で特定する。例えば、PATHからこれらを外した一時環境で、候補ファイルを `pytest -n 0` で実行する。
   - 各テストについて、次を表にする。
     - 何を守っているか（本体のエンコード引数、出力形式、Drive操作の実挙動など）
     - 依存が無いときの現在の挙動（失敗、skip、黙って通過）
     - CIのどのレーンに割り当てられているか
   - 本体コードのうち、ffmpeg・rcloneの実行ファイルを呼ぶ箇所の一覧も付ける。
3. **対策案の比較。** 次の案と、その組合せを比較し、推奨を1つ選んで理由を書く。比較の観点は、検出力（失う検証と、その代替）、保守、供給網の安全、CI時間、障害時の挙動、repoの方針（静かなフォールバックの禁止）との整合。
   - A. システム依存テストを明示のmarkerで分け、通常のCPUレーンでは準備しない。対象テストをどこで検証するかも決める（専用レーン、ローカル、定期実行）。
   - B. 動画の書き出しを、既存依存のPyAV（`av`）へ移し、ffmpegの実行ファイルを不要にする。現在のH.264・画素形式・速度・品質の設定を保てるかを、PyAVのwheelが含むコーデック（libx264の有無）で確かめる。
   - C. ffmpeg・rcloneを、SHA-256を照合した固定版の取得に変え、aptを使わない。
   - D. apt取得物のキャッシュ、または固定した代替配布元の追加。
   各案で、実装範囲（変更ファイル）、テスト設計、所要時間の見積もりを示す。#1857・PR #1858 との関係（取り込む、置き換える、独立）も書く。
