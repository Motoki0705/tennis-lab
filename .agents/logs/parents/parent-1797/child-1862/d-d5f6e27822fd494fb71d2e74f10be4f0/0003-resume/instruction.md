## 親の判断（調査報告への回答）と実装指示

報告を確認し、推奨方式（prepare時に選択をrequest version 3へ固定し、execution・runtime・公開証拠を同じ検証部品で照合する）で実装へ進む。報告で親の判断を求められた4点は、次のとおり決める。

1. Solの初期effortは xhigh とする（許可する組は `gpt-6.1-sol:xhigh` と `gpt-6-astra:xhigh`）。比較評価は #1863 で行い、その結果で見直す。
2. fixedでは、明示指定は固定値と一致する場合だけ許し、異なる指定は起動前に拒否する。既定は fixed のままにする。
3. 復旧要求（recover）には、元run参照を固定する入力を設ける。実効モデルは、元runの検証済み値として表示する。採用先requestの既定値を、実行モデルとして記録しない。
4. 子3ではPR内のcoverage合成を追加しない。引継ぎ（Sol→Astra）は元runとの対応を記録するだけにし、coverageは既存のPR単位の契約を維持する。部分的な確認しかできない場合は、not_reviewedでgateを止める。

追加の指示:
- service tierは、現行どおり理由付きの `unavailable` を許す。観測できた場合だけ一致を要求する。
- `parent/execution.py` のrequirements照合（現在はversion 2限定）など、version 3の追加で照合を飛ばす箇所が出ないよう、旧版との分岐をテストで固定する。
- #1796接続（判断記録の選択元）は、`--review-model` などの選択元を判断記録が正しく区別できるよう、最小限の接続点だけを用意する。本格的な接続は #1863 で行う。
- 既定fixedでの退行確認には、報告で挙げた既存nodeを使う。ラップトップでtimeoutする既存nodeは、修正前の基準結果と比べ、CIで通過を確認する。
- `.agents/ops/lib` の他profile（実装worker、ops_report・ops_scout・issue_judgement、agy・説明HTML）の設定・argv・継続契約が変わらないことを、テストで確認する。

制約は前回と同じ。
- pytestは `-n 0` で、対象のnode・ファイルだけを順に実行する。メモリ不足で一度停止したので、同時実行や大きな一括処理を避ける。全体はCIで確認する。
- CIの基盤由来の失敗（apt取得の時間切れ、ネットワーク切断）は、ログを確認したうえで、失敗ジョブの再実行を1回までにする。結果はPR本文に書く。
- 作業時間の目安は最大8時間。
- 止めてよいのは、受入条件をすべて満たしてPRを作成し、CI結果を確認したとき、または判断が必要な矛盾があって他の作業単位も進められないときだけ。
- PRは日本語で書き、`Closes #1862` を入れる。mergeはしない。
- 最終報告では、全角スラッシュ「[local path]」を使わない（作業ログの公開検査で誤検出される）。
