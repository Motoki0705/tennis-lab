# テーマ設定

テーマissueは人間とAIの唯一の合意点。ここで固定した内容が、以降の自律サイクルの
契約になる。template: [04_research_theme.md](../../../../.github/ISSUE_TEMPLATE/04_research_theme.md)
（タイトル `[研究テーマ] `、ラベル `research`）。

## AIが用意するもの

人間の問題提起を受けて、AIは次を下書きして提案する。決めるのは人間。

1. **問題提起**: 何が分かれば/できれば前進か。対象タスクと、関連する
   knowledgeノード・論文ID（[summary.md](../../../../knowledge/summary.md) から）。
2. **目標指標**: 指標名、単位、向き（大/小が良い）、現状のbaselineとその根拠ノード。
   副指標（悪化させてはいけないもの）があれば併記する。
3. **評価条件**: split、seed数、評価スクリプト/コマンド、比較の単位（run / group）。
   サイクルをまたいで同一条件で比べられることが要件。
4. **停止条件**: 下の指針から、この指標に合うものを提案する。
5. **予算の目安**: GPU時間・サイクル数の上限、Colab利用の可否。
6. **候補手法**（任意）: 人間が既に持っている候補。AIの調査で増減してよい。

## 停止条件の提案指針

共通ルールは置かない。指標の性質を見て、少なくとも「成功」「打ち切り」の両方を書く。

- **seed間ばらつきが大きい指標**: baselineを固定seed数で測り直し、改善幅が
  seed間標準偏差を明確に超えることを成功条件にする（例: 平均差 > 2σ、全seedで同符号）。
  seed数はばらつきとGPU予算から提案する。
- **ほぼ決定的な評価**（固定ckpt・固定データの推論評価など）: 絶対閾値で判定してよい。
- **上限・飽和がある指標**（accuracy, recall等）: 目標値か、残差の何割削減かで書く。
- **連続改善型**: N サイクル連続で改善が閾値未満なら打ち切り（プラトー判定）。
- **探索・調査型**（実装可能性、データの性質の把握など）: 答えるべき問いを列挙し、
  すべてに証拠つきで答えたら終了。
- **共通の打ち切り**: 予算到達、または同じ失敗原因が続き次の打ち手が無いとき。

## 最小形（1サイクルで止まるテーマ）

従来の「人間とAIでissueを作り、AIが検証してレポートする」運用は、停止条件を
「1サイクル完了」としたテーマとして扱う。手順は通常と同じ（サイクル子issueを1つ作る）。
既存の調査issueを起点にする場合は、その本文に上の固定項目を補ってテーマとして扱う。

## 固定後の扱い

合意したら、本文末尾に合意日と合意者を書く。目標指標・評価条件・停止条件の変更は
人間との再合意が必要で、変更履歴を本文に残す。候補手法や予算配分の内訳はAIの判断で
変えてよい（理由はサイクルissueに書く）。
