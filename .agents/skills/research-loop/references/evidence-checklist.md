# 結果から主張へのチェックリスト

サイクルの考察を書く前に、各主張についてknowledgeノードの実測から確かめる。
最適化するエージェントが陥りやすい失敗を防ぐためのもので、研究の質を保証するものではない。
可能なら別のエージェント（Claude↔Codex）にこの表で監査を頼む。

## 実験の健全性

| 観点 | 確認すること | 不合格の例 |
|---|---|---|
| 正解の出所 | 正解ラベルはデータセット由来か。モデル出力から作っていないか | 別モデルの予測を正解として一致率を報告 |
| 指標の正規化 | 自分の出力の最大値・平均などで割っていないか。生の値も出しているか | 自己正規化で0.99 |
| 結果の実在 | 主張する数値がノードの `metrics` と、そのrunの出力に実在するか | ログに無い数値、未完了jobの数値 |
| 評価の一致 | テーマで固定したsplit・seed数・評価コマンドのままか | 一部seedだけ、別splitでの比較 |
| 範囲 | 主張の言葉が、実際のデータ数・seed数・条件数に見合うか | 1クリップで「頑健」 |
| 失敗の扱い | 失敗・中断runを除外していないか。除外したなら理由を書いたか | 良いseedだけ残す |

評価の種類を明記し、主張の上限を合わせる。

| 種類 | 意味 | 言える範囲 |
|---|---|---|
| 実データ正解 | データセットの正解との比較 | 性能の主張 |
| 合成データ | シミュレーション・合成シーンでの評価 | 「合成データ上で」の限定つき |
| 代理指標 | 正解なし（再投影誤差、一貫性など） | 相対比較のみ |
| 目視 | 動画・図の目視確認 | 観察として記述し、指標としては扱わない |

## 主張の判定

各主張について、サイクルissueの考察に次を書く。

- **判定**: 支持 / 部分的に支持 / 不支持 / 判定不能
- **根拠**: ノードIDと、その中の値
- **言えないこと**: データ・条件・seedの範囲外
- **不足している証拠と、それを埋める実験**（次サイクル提案の材料）

1つのデータ・1つの条件での改善は、一般的な主張を支持しない。部分的支持を
丸めて支持にしない。判定不能は「追加実験が必要」として扱う。
