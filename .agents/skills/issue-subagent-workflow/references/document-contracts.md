# Document contracts

Every artifact begins with the Issue number, current attempt, and status. Implementation and test artifacts also record the current test-cycle number. Remove all placeholders before submitting a transition or verdict.

## `issue.md`

Generated by the initializer and immutable during an attempt. The Issue body must contain at least one Markdown task-list item under the exact `## Acceptance checklist` heading. Items are normalized to stable IDs `AC-001`, `AC-002`, and so on. The checklist count and SHA-256 are recorded in both `issue.md` and `state.toml`.

The normalized checklist is authoritative. Original `[x]` or `[ ]` state is metadata only. Duplicate or missing items fail initialization.

## `state.toml`

Schema version 3 records:

- frozen Issue and checklist identity;
- current Issue attempt and phase;
- `test_cycle`, the number of completed independent test evaluations;
- `test_verdict`, empty, `PASS`, or `RETURN`;
- final validator verdict and task status.

Tester RETURN keeps the same Issue attempt and implementation phase. Validator RETURN increments the Issue attempt, resets tester state, and returns to exploration.

## `01-exploration/exploration.md`

Required sections:

- Scope and Issue interpretation
- Relevant files and symbols
- Entry points and execution paths
- Data, configuration, and interface contracts
- Existing tests and fixtures
- Invariants and compatibility constraints
- Risks and likely impact radius
- Unresolved questions
- Evidence table distinguishing fact, inference, and unknown

A path list without traced behavior is insufficient.

## `02-planning/plan.md`

Owned only by the parent. It must include the frozen checklist hash and exactly one ordered table row for every AC ID and exact Issue item text. Every row maps to an implementation action and authoritative validation method. Merely mentioning AC IDs elsewhere does not satisfy the contract.

## `03-implementation/implementation.md`

Required metadata:

- Issue number
- current Issue attempt
- next test-cycle number
- status

Required sections:

- Assigned ownership
- Files and symbols changed
- Behavior implemented
- Plan deviations and rationale
- Commands and results
- Known limitations and remaining risks
- Handoff

On tester RETURN, the Implementer overwrites this file for the next test cycle and records how each returned failure was addressed. It must not modify the independently authored tests.

## `03-implementation/tests.md`

Required metadata:

- Issue number
- current Issue attempt
- current test-cycle number
- frozen checklist hash
- status

Required sections:

- Acceptance-checklist-to-test mapping
- Tests added or changed
- Normal, boundary, invalid, and regression cases
- Commands and exact outcomes
- Failures encountered
- Untested risks and reasons
- Final test verdict
- RETURN implementation findings

The mapping table must contain exactly one ordered row for every AC ID and exact Issue item text. Requirements not provable by automated tests must identify the authoritative evidence the Validator should collect.

The final tester verdict is exactly one standalone `PASS` or `RETURN`:

- `PASS`: relevant independent tests and commands succeeded, with no known production failure in scope.
- `RETURN`: production behavior, testability, or required integration is inadequate. The RETURN findings must contain actionable failures for the Implementer.

The Test Writer never changes production code to obtain PASS.

## `04-validation/validation.md`

Required sections:

- Frozen Issue and checklist hashes
- Inspection scope and revision
- Acceptance checklist verification matrix
- Exactly one ordered row for every AC ID and exact Issue item text
- A verdict of `PASS`, `FAIL`, or `NOT VERIFIED` with direct evidence for each row
- Code evidence
- Runtime and test evidence
- Regression and repository-rule checks
- Final verdict
- RETURN exploration questions

Validator PASS requires every AC row to be PASS. Validator RETURN requires at least one FAIL or NOT VERIFIED row. The helper mechanically rejects missing, duplicated, reordered, unknown, or text-mismatched rows.
