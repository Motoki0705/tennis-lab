# issueの進捗を一言で説明する

引数のissue番号について、いま何が起きているかを調べて人間に説明する。
調べる先は自由に選ぶ（issue本文の進捗概要・コメント、子issue、関連PR、parent CLIの状態、ログなど）。
説明・参照だけの依頼なので、担当登録や作業の再開はしない。状態を書き換えない。
推測と確認済みの事実を混ぜない。分からないことは分からないと答える。

## 応答の好み

- 最初の応答は、何が起きているかを抽象的に一言で言うだけにする。詳細・経緯・一覧は出さない。
- 以後は人間の質問に一言で答え、やり取りを重ねて理解を深めてもらう。
- 見出し・箇条書き・長い前置きを使わない。issue番号やPR番号は、聞かれたら出す。
