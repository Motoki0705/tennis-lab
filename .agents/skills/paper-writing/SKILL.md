# 技術報告の制作

担当 issue の範囲、合意済みの主張、到達すべき工程を確認する。各工程の成果を次の工程の入力にする。テニスシーン再構成の報告では [設計書](../../../paper/tennis_scene_architecture/design.md) と [LaTeX 雛形](../../../paper/tennis_scene_architecture/README.md) を使う。

## 1. 設計

- **入力**は人間との合意、対象 pipeline の仕様、既存の実験・文献記録。
- **成果物**は `design.md`。主題、読者、貢献、章立て、節ごとの主張と根拠候補、必要な追加検証と担当 issue を記す。
- **確認**では各貢献に対応する章があり、その章の主張をどの観測・比較で確かめるかが決まっていることを照合する。

## 2. 根拠の対応表

- **入力**は設計書、[knowledge のノードと run](../../../knowledge/README.md)、検証 issue の成果、図表の元データ、文献の一次資料。
- **成果物**は `evidence/` の対応表。本文・図表の各実測値と集計値に、掲載箇所、指標・単位・分母、評価条件、knowledge ノード・run ID・保存ファイルを対応づける。図表には元データのパスと版、生成コマンド、出力パスを記し、既存図版を使うときは元ファイルのハッシュも残す。
- **確認**では出典を開いて値と条件を照合する。比較の可否は [結果を解釈するための規則](../../../knowledge/summary.md#結果を解釈するための規則) に従う。検証結果が合意済みの主張と異なる場合は観測値と条件をそのまま記録し、主張との差を親へ報告する。出典を確認できていない項目は検証 issue に結び付ける。

## 3. 執筆

- **入力**は設計書、確認済みの対応表、LaTeX 雛形。
- **成果物**は全章・付録の初稿、図表、図表生成スクリプト、参考文献。図表は保存済みデータ・画像から生成する。既存資産の使い方は [コート検出報告の同梱物と再生成手順](../../../paper/court_robustness/README.md#同梱物) を参照する。
- **確認**では本文・キャプション・表の値を対応表に突き合わせ、引用先の実在と引用箇所の対応を確認する。全章を書き上げてから推敲に入る。

図表や根拠資料を追加したら、雛形の登録手順に沿ってファイルを確認する。[Gitへの登録](../../../paper/tennis_scene_architecture/README.md#gitへの登録)

## 4. 推敲

- **入力**は全文の初稿、図表、対応表。
- **成果物**は内容を照合した改稿。結果の直後に繰り返す留保や、適用範囲を示さない曖昧な但し書きを除く。解釈に必要な条件は結果の文またはキャプションに添え、未評価の範囲は限界の節で具体的に記す。
- **確認**では初稿との差分を読み、各文が伝える事実を確かめる。数値・単位・分母・出典と、主張を支える評価条件を対応表で再照合する。

## 5. ビルドと最終確認

- **入力**は改稿、図表、参考文献、報告ディレクトリの README にある組版手順。
- **成果物**は PDF とビルド記録。記録には原稿の版、コマンドと終了値、組版環境、ページ数、PDF のハッシュ、確認結果を残す。[コート検出報告の組版手順](../../../paper/court_robustness/README.md#pdfを再ビルド) と [ビルド記録](../../../paper/court_robustness/evidence/build.json) を参照する。
- **確認**では最終ログの未解決参照・引用、欠落文字、はみ出しを調べる。PDF を開き、全図表とキャプション、本文からの参照、参考文献、改ページと余白を確認する。
